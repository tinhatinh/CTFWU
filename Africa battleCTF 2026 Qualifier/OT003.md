# OT#003 — Blast furnace portal: SSRF vào emergency stop không được bảo vệ

**Flag:** CTF{49b7d0bdb03d054b68dc793abae27fcf}  
**Service:** http://169.58.126.107:6002  
**Định dạng flag:** CTF{...}

## Đề bài

> OT#003 — 136 điểm. Đây là portal vận hành từ xa cho blast furnace, nằm ở phía corporate của mạng nhà máy thép. Control system của furnace không thể truy cập trực tiếp; chỉ có web portal này.

Portal là ứng dụng Express sau openresty. Nó có form đăng nhập, dashboard và “sensor integration test tool”. Mạng nhà máy phía sau chứa furnace controller thật trong internal Docker network; đường khai thác dự kiến là portal → SSRF → internal control API → hành động process không an toàn.

## Phân tích

### Recon portal

Portal nhận diện là openresty/1.31.1.1 với X-Powered-By: Express. Bề mặt truy cập nhỏ:

| Path | Hành vi |
|---|---|
| /login | form đăng nhập |
| /dashboard | cần session cookie sid; nếu thiếu thì 302 về /login |
| /ops/test-sensor | POST endpoint được dashboard “Sensor integration test tool” dùng |
| /commissioning-notes.txt | ghi chú commissioning bị lộ |

File commissioning notes là sai sót đầu tiên:
 
```text
Furnace 2 remote portal - commissioning notes
-----------------------------------------------
Default operator account created for initial testing:
  username: operator
  password: St33lW0rks!2024
TODO: rotate this before go-live and use SSO instead.
(ticket ORD-4471, still open)
```

Đăng nhập operator:St33lW0rks!2024 sẽ nhận sid cookie 32 hex và vào được /dashboard.

### SSRF

Tool trên dashboard POST form field url, method và body tới /ops/test-sensor. Backend dùng node-fetch để tải URL rồi trả {"status":<code>,"body":<response>}. Nó gắn thêm X-Session-Id: <sid> vào outbound request và hardcode Content-Type: application/json.

Fetcher có blocklist nhưng kiểm tra raw string:

- Từ chối localhost, 127.0.0.1 và các private range thường gặp.
- Từ chối URL có chuỗi furnace viết nguyên văn.

So sánh phân biệt hoa thường và chạy trước khi parse URL, nên hai cách dưới đây bypass được:
 
```text
http://FURNACE:4000/status
http://%66urnace:4000/status
```

HTTP client tự lower-case Host header nên internal DNS name vẫn resolve bình thường.

### Mạng nội bộ

SSRF chạm được Docker network 172.25.0.0/24 gồm ba host:

| Tên | Địa chỉ | Service |
|---|---|---|
| furnace | 172.25.0.2 | furnace control API trên 4000 |
| gateway | 172.25.0.3 | chính portal trên 3000 |
| nginx | 172.25.0.4 | front của portal trên 80 |

Thoạt nhìn furnace API chỉ có hai route:
 
```json
GET /status
{"temperature":1550,"pressure":92,"vented":false,"ruptured":false}

POST /vent
{"ok":true,"pressure":35,"vented":true}
```

State gắn với header X-Session-Id — tức riêng từng portal login. Đăng nhập lại reset furnace về baseline (pressure 92, chưa vent). Điều này ảnh hưởng exploit: cần thực hiện unsafe action khi pressure còn cao.

Portal giới hạn SSRF tool ở 25 request mỗi session; login mới reset quota.

### Lỗi process safety

POST /vent hạ pressure còn 35 và đặt vented:true. Emergency shutdown route không xuất hiện trên portal; quét từ route wordlist tới internal API tìm được:
 
```text
POST /emergency_stop
```

Nếu furnace còn áp suất khi emergency stop chạy, controller sẽ shutdown mất kiểm soát:
 
```json
{"error":"Uncontrolled shutdown with pressure still high: vessel ruptured."}
```

GET /status sau đó trả ruptured:true kèm flag. Vent trước sẽ làm shutdown an toàn và flag không xuất hiện — lỗi mục tiêu là operator (hoặc attacker) bấm emergency stop mà chưa vent vessel.

## Ghi chú

- Điểm đáng chú ý không chỉ là SSRF mà là logic OT: emergency stop được thiết kế để dừng process nhưng không xả áp suất còn lại, nên caller không tin cậy có thể biến thao tác an toàn thành sự cố vỡ vessel.
- Raw-string blocklist nhận cả hostname viết hoa và ký tự đầu được percent-encode. Đây không phải bypass tinh vi; portal không canonicalize URL trước khi so sánh.
- Flag nằm trong furnace state object và chỉ xuất hiện khi trạng thái là ruptured:true.
