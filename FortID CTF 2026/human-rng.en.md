# Human RNG

**Flag:** `FortID{humans_are_not_good_random_number_generators}`
**Artifact:** `handout.zip` (2.5 KB) plus a Google Drive video (`https://drive.google.com/file/d/1Tsh7dtCGCfWhUliPvIkmd0bUo9f5XCvo/view`). No instancer. Authors: ipaljak, laragrr.

## Challenge

Artifacts only, no service. `handout.zip` (2.5 KB) ships together with a Google Drive video that records how the QR module pattern was produced; the video is the only source of the human data.

The crux of the challenge: the QR module pattern was not generated by a QR library, it was typed out by humans. The bit sequence derived from that pattern is therefore not a sample from a PRNG, and it can be reversed statistically. The challenge publishes no generator model; every constraint below comes from measurement over the artifact.

## Analysis

### The two statistics that define the problem

For a bit sequence, the record uses two quantities: the frequency of `1` bits, and the frequency with which the value changes between adjacent positions (`flip`).

```python
def stats(bits):
    """P(1) and the rate of flips between adjacent positions."""
    p1 = sum(bits) / len(bits)
    flip = sum(a != b for a, b in zip(bits, bits[1:])) / (len(bits) - 1)
    return p1, flip


recovered = (0.4848, 0.7238)   # statistics of the recovered keystream
human = (0.4747, 0.7017)       # statistics measured for human-produced bits

print("dP(1) :", round(recovered[0] - human[0], 4))
print("dflip :", round(recovered[1] - human[1], 4))
print("flip expectation for independent fair bits: 0.5")
```

```text
dP(1) : 0.0101
dflip : 0.0221
flip expectation for independent fair bits: 0.5
```

The recovered keystream measures `P(1) = 0.4848` and `flip = 0.7238`; the reference human-behaviour measurements are `0.4747` and `0.7017`. The gaps are 0.0101 and 0.0221, so the recovered pair sits close to the human model.

The arithmetic of `flip` is where the challenge opens up: for independent, balanced bits the probability that adjacent positions differ is `2pq = 0.5`. Both 0.7238 and the human 0.7017 are far from 0.5, meaning the sequence changes value far too often — the standard bias of people asked to "be random". Since the source sequence is human behaviour, the rest of the problem is an estimation task over a finite candidate set, not a decryption under a secret key.

### Sweeping the candidate space

The bit positions not locked down by the anchors (the mid-token positions) were swept exhaustively: 45.8M candidates. Each candidate was scored with the two statistics above, normalised into a z-score against the measured human-behaviour distribution.

The sweep produced one clearly separated outlier: `z = +14.77`, while the runner-up stopped at `+13.01` (a gap of 1.76). That gap is what justified the selection, not what justifies the conclusion.

## Solution

The winning candidate was used to rebuild the module matrix and the ciphertext; the verification pipeline prints numbered fields. The verification line is recorded verbatim below, where the `…` is an elision made by the record itself and the fields `1)` and `3)` are not present in it:

```text
2) anchors : 522/522 … 4) reconstruct ct : True | 5) OpenCV QR read : 'FortID{humans_are_not_good_random_number_generators}' | FLAG = FortID{humans_are_not_good_random_number_generators}
```

The three preserved fields mean:

- `anchors : 522/522` — all 522 anchors of the rebuilt matrix agree with the constraints taken from the artifact.
- `reconstruct ct : True` — the reconstructed ciphertext satisfies its own consistency check.
- `OpenCV QR read` — a QR decoder reads the freshly rebuilt matrix and returns exactly the flag string. This is the most important field as evidence: it does not use the z-score, but the decoded matrix was still built from a candidate selected by the behavioural model.

The API shape behind step `5)`:

```python
import cv2

det = cv2.QRCodeDetector()
text, points, straight = det.detectAndDecode(matrix)   # matrix: uint8 ndarray of the rebuilt pattern
print(text)
```

## Result

```text
FortID{humans_are_not_good_random_number_generators}
```

The 52-character string is retained from the saved verification line. Without the matrix and solver, neither QR decoding nor the statistical search has been reproduced. No submission response was preserved.

## Reproduce

You need `handout.zip`, the linked video, Python 3 with `numpy` and `opencv-python` (the `cv2.QRCodeDetector` API).

1. Take the source bit sequence from the artifact/video.
2. Compute the two statistics and their distance to the human model — the `python` block in the Analysis section runs standalone on the recorded constants and prints the three output lines that follow it.
3. Sweep the mid-token positions (45.8M candidates), normalise each score into a z-score against the human-behaviour distribution, keep the extreme candidate (`+14.77`).
4. Rebuild the matrix and the ciphertext from that candidate; check the 522 anchors and the reconstruction constraint.
5. Read the matrix with the `python` block for step `5)`; the printed string is the flag.

Steps 1, 3 and 4 operate directly on `handout.zip` and the video; the record for this challenge preserves the measured numbers (0.4848 / 0.7238, 0.4747 / 0.7017, 45.8M candidates, +14.77 / +13.01, 522/522) and the verification line, but not the sweep script, so a full reproduction of those steps has to be rebuilt from the artifact itself. The 45.8M-candidate sweep is the expensive part; it runs locally and touches no service.
